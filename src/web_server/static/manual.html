    3 Games Night

    A suite of party games, duels, and group elimination games for hangouts and game nights. Everything is member-facing — anyone can start a game in an allowed channel. Only one game runs per channel at a time. Type /games help in Discord for the in-app version of this list.

    💡
    Channel allowlist & NSFW

    Games only run in channels an admin has allowlisted on the Games Config panel in the web dashboard. Spicier (NSFW) prompts are served only in channels marked age-restricted in Discord; every other channel stays SFW.

    Party Games

    All start with /games play <mode>, Everyone in allowed channels. Most run in rounds: a host starts the game, players join or vote with buttons, and the host advances rounds. Prompts come from the question bank — see For hosts & admins.

    ⏰
    Give people time to show up: start_in:

    Six games open a lobby and wait for you to press start — Clapback, Spin the Compliment, Marry, Fornicate, Kiss, Most Likely To, Mt. Rushmore Draft and Story Builder. Add start_in: (1–60 minutes) when you open one and the lobby shows a live countdown, so people know when to be there — e.g. /games play rushmore start_in:15.

    The game does not start by itself. When the countdown runs out the bot posts a message in the channel tagging you, so you don't have to watch the clock — you still press the button when everyone's in. Most games that aren't on that list begin the moment you run the command, so they have no start_in:.

    Scheduled games work the same way: if an admin has one of those six on a schedule, the bot tags whoever set it up as soon as the lobby appears, since someone still has to start it.

    Two Truths and a Lie, Hot Takes and LegitLibs also wait on the host, but don't take start_in: yet.

    🏷️
    Nickname stakes & staff

    By default the loser surrenders their nickname for a set sentence, so the bot needs the Manage Nicknames permission — without it these games can't run. A player whose top role sits above the bot's (a staff member, say) can still play: the game shows a heads-up that it won't be able to rename them, and if they lose the win still counts — their nickname just isn't changed. To let the bot rename them too, move its role above theirs in Server Settings → Roles.

    💰
    Coin wagers

    All six duel and group games take an optional wager: amount — every player antes the same, and the winner takes the pot. Some servers set a small house cut on won pots; when one applies, the payout message says exactly how much the house kept. Refunds are never cut. In a 1-v-1 challenge nothing is charged until the target accepts (declining or letting it time out costs nothing); in a lobby game you pay as you join, and leaving the lobby refunds you. If a game is abandoned, voided, canceled, or ends with no winner, every stake is returned — and if you leave the server mid-game your stake comes back automatically. Wagers need the economy enabled and use your /bank wallet balance. A wager replaces the usual nickname stake: the pot is what's on the line, so the winner doesn't get the rename button. Nicknames are only at stake in the default game — no wager:, no custom stakes:.

    For Hosts & Admins

    /games config game-status    /games end force:true Mod Show the active game in the current channel, or force-close it if it's stuck. The games channel allowlist and the audit log channel are managed on Games → Global Config in the web dashboard.

    External game tracking lives on the dashboard under Games → External Tracking — it replaced the /games track commands. The bot watches a channel where another game bot (Gamebot's Cards Against Humanity, Connect 4 and Anagrams; Cat Bot; Wordle; Co-ordle) posts results, and pays economy rewards for wins and catches. Wordle pays out on the daily group digest — solving in fewer guesses earns more, and everyone tied for 👑 gets the win bonus. Co-ordle pays each round once it's solved or runs out of rows, splitting by the points each player earned.

    On the panel: add a watch by picking a channel, the game bot, and the format. Add one per channel to track a bot that plays in several — games running in different channels at the same time each pay out on their own. Each row shows how many messages it has banked, with Pause/Resume (data is kept while paused) and Sample, which dumps that bot's recent messages so you can confirm the format parses before trusting the payouts.

    4 Photo Challenge

    A standalone scheduled photo feature (it used to live in the Games suite). On its configured schedule the bot posts a photo-prompt card to a dedicated Photo Challenge channel, optionally pinging a role. Members answer by posting their photos in that same channel — no commands involved.

    💡
    Posting is the reward

    When the Economy is running, simply posting an image in the Photo Challenge channel pays out a flat participation award — no reactions or replies needed. If there's also an active photo_post quest, its reward stacks on top of the participation award. Both are capped at once per member per day, no matter how many photos you post.

    ℹ️
    Configure via the web dashboard

    Admins (or the game-host role) set the channel, ping role, recurring schedule, and enabled toggle on the Photo Challenge → Setup & Schedule panel. The flat participation award is a faucet rate on Economy → Income Sources ("Photo Challenge post"); the optional stacking bonus is a photo_post quest in Economy → Quests. The prompt bank lives on that same panel. The old /games play photo command is retired.

    7 Confessions

    Anonymous Confessions

    The confessions system lets members post anonymously to a configured channel. Each confessor is assigned a colored emoji (e.g. 🔴🟢🔵) so mods can identify repeat posters without exposing identity to other members.

    /confess Everyone Opens an anonymous submission modal (up to 4,000 characters). The confession is posted to the confessions channel with a colored emoji identifier visible only to mods.
    ℹ️
    Mod capabilities in confessions

    Mods can see the emoji→member mapping in the mod log channel, block a specific member from confessing (without revealing their identity), and enable panic mode to temporarily suspend all new confessions.

    8 Pen Pals

    Pen Pals quietly matches members into private one-on-one conversations. How you're matched depends on the server's Pairing Mode, set on the dashboard: Instant matches you straight away if someone eligible is already waiting, otherwise you sit in the pool and are matched the moment the next person joins; Once a day never matches on join — everyone who joins queues up and the whole pool is paired in one batch at 8:00 AM Eastern. Either way the bot spins up a private two-person channel, seeds it with a conversation-starter question, and tears it down again after a configurable session length (default 24 hours). Nobody is ever in two pen pal chats at once, and after a chat ends there's a re-match cooldown (set on the dashboard) before you can be paired again. You're never matched with the same person twice — once two members have been pen pals, Pen Pals won't put them together again, so if everyone waiting is someone you've already had you simply stay in the pool until a new face joins. If there's someone you'd rather not be matched with, /penpals block keeps the two of you apart — privately, and one block is enough.

    CommandPermissionWhat it does
    /penpals joinEveryoneGet a pen pal — instant mode matches you on the spot if someone's waiting, otherwise (or in "once a day" mode) you join the pool and wait for the next match
    /penpals leaveEveryoneLeave the pool before you're matched
    /penpals statusEveryoneWhether you're waiting or matched, and when your session ends
    /penpals blockEveryoneOpen a private panel to pick members Pen Pals should never match you with (or unblock them) — one block is enough, the other person is never told, and it doesn't end a chat you're already in
    /penpals new-questionEveryoneSwap the current conversation-starter for a fresh one (limited swaps per session)
    /penpals endEveryoneEnd your current session early and close the shared channel
    /penpals pair <user1> <user2>ModForce-pair two specific members, bypassing the pool — both must already have joined the pool, so force-pairing never overrides opt-in
    /penpals roundModForce a pool sweep right now, instead of waiting for the automatic sweep (every few minutes in Instant mode, once a day at 8am Eastern in Once-a-day mode)
    ℹ️
    Configure via the web dashboard

    The Games → Pen Pals panel holds the whole feature on one page: the enable toggle and wiring (channel category), session length, and the re-match cooldown, with the conversation-starter question bank below them. Moderators can change both halves — Pen Pals settings are moderator-level rather than admin-only, so whoever curates the prompts can also set the channel they post in. Pairing Mode picks how matches happen — Instant (the default) matches the moment a partner is waiting, or Once a day to queue everyone and pair the whole pool in a single batch at 8:00 AM Eastern instead. Who Can See Each Chat controls how much staff oversight the private rooms get — Admins only, Admins and mods (the default), or Everyone (anyone can read the chat but only the two members can post). It applies to chats opened after you save; chats already running keep their original visibility. Session Opening Message is an optional note you write once — it's shown at the top of the pinned intro embed every time a chat opens, above who's matched and when the chat ends. Leave it blank for no message.

    When a message receives enough star reactions, it's reposted to the starboard channel as a highlight. The channel, threshold, emoji, and exclusion list are configured in the Starboard panel on the web dashboard.

    10 Economy & Perk Shop

    A per-server currency (branded per guild — name, emoji, and wallet name are all configurable) earned by being active and spent on weekly-renewing perks. There's no grinding loop of earn commands: currency flows from the activity you're already doing — logging in, hanging out in voice, playing games, answering the question of the day, and completing quests. The economy is off until an admin enables it and sets a bank channel.

    Earning

    • Daily login — your first counted message or qualifying voice session of the day pays a small login reward (voice pays more than text; if you've already claimed the day by typing, joining voice later tops you up to the voice rate). Consecutive days build a streak bonus, one missed day per week is silently forgiven, and streak milestones (day 7, 30, 100…) pay extra. If you've opted into economy DMs (the server's configured game role), each login sends you a little digest — your streak, and a checklist of open quests with progress bars, so you always know what's worth doing today.
    • Quests — daily and weekly quests drawn onto your personal board, plus server-wide goals: a monthly goal and community goals that everyone contributes to together, and event quests. Many complete automatically when you do the thing (send a trigger phrase, play a game, post a photo, answer a chat-revive prompt, host a voice hangout, set a bio…); others you claim from /bank quests, and some need a staff sign-off before paying. The monthly goal is a shared, server-wide target for the calendar month — everyone's activity moves one progress bar, and when the server crosses the 40% / 70% / 100% marks everyone who's been active gets paid; there's one running at a time and it isn't something you claim. Some quests travel in pairs — draw one half (say, submit a Guess Who round) and its partner (play a round) lands on your board with it. Getting-started nudges — one-time setup tasks like filling out your bio, setting your birthday, picking a role, or making your first shop purchase — hold a slot on your daily board until you've done them, then quietly drop off for good (a new member may see a board that's mostly nudges at first; each clears in one action, and a 🎲 reroll pushes one off if you'd rather skip it). Your board is frozen for the period it was drawn for: when staff add, edit, or retire quests, the change lands at the next daily / weekly roll, so nothing you're partway through disappears mid-period.
    • Community weeklies — the server runs up to two shared goals at once ("send 3,000 messages together"), each sized automatically from recent activity. They sit in two lanes: one takes a week off after it finishes ("let the win breathe"), the other refills straight away, so the board is rarely empty. Everyone's actions count automatically, milestones at 40/70/100% each pay every active member, and the top contributors earn a bonus — so even a partial week pays out.
    • Board extras — one free 🎲 reroll per day on /bank quests swaps out a quest that doesn't fit you, and you can buy a few more that day if you want another swap (the select tells you the price). Clearing your whole daily or weekly board pays a set bonus, and each week one ⚡ spotlight activity pays double (announced when the new week's quests go up).
    • Games & QOTD — playing a party game or duel pays participation (winning pays more — every game with a real winner now pays its champion, and the game's results card shows the amounts). Hosting a party game that other people join can pay the host a bounty too (scaled by how many turned up — starting a game nobody joins doesn't count), and may complete a "host a game" quest. Replying to the question of the day pays once per QOTD — use Discord's reply on the question itself; just talking in the channel doesn't count, and yesterday's question stops paying when the day rolls over.
    • Coin drops — where the server has turned them on, the bot occasionally drops a pouch of coins into a chat channel at unpredictable moments. First member to hit the 🪙 Claim button grabs the whole pouch; the message updates to show who got it, and anyone slower is told so privately. Unclaimed pouches vanish after a while. Drops only land where there's conversation — you can't camp a dead channel waiting for one.
    • Chat XP — where the server has switched this on, the XP you earn from posting, replying and voice converts into coins automatically at the end of each server day; you don't claim it, it just lands.     Casino

    Where the server has opened it, one channel becomes the casino floor: the bot keeps a 🎲 Golden Meadow panel there with a button per table, and everything happens through those buttons — there are no casino commands.     • 🎰 Slots — three spinning reels in a little slot-machine cabinet.     • 🃏 Blackjack — hit, stand, or double down against the dealer. Dealer stands on 17; a natural blackjack pays 3:2. Wander off and your hand stands itself; if the bot restarts mid-hand, your bet comes back.

    • 🏇 Derby — one press sends six meadow critters to the starting gate and opens a betting window for the whole channel.     • 🎴 Baccarat — one press opens a betting window for the whole channel. Back the Player or the Banker (both pay 2× — the best odds in the house; ties hand your bet back, and a Banker win on a three-card seven pushes instead of paying) or the long-shot Tie at 9×. When the window closes the cards fall by baccarat's fixed drawing rules — no decisions, nearest to nine wins, everyone settles at once.
    • 🎲 Dice — one press opens a betting window for the whole channel. Three dice, one shared roll: call Big (11–17), Small (4–10), Odd, or Even — all pay 2×, but any triple sweeps the table for the house. When the window closes, one roll settles everyone at once.
    • ⚔️ War — the fastest table in the house: one card each, aces high, the higher card pays 2× on the spot. Going to war is always the better play, and if you wander off mid-standoff the house goes to war for you (or retreats if you can't cover the raise).

    The tables have a sense of occasion: big bets get the show (reels stopping one by one, the dealer pausing on the hole card, the roulette ball bouncing before it lands), wins of 10× or better go gold, and hot or cold streaks of three-plus get called out on your results. /bank wallet keeps your personal tally — wagered, returned, net, biggest win, current streak — and the live leaderboard's Night at the Tables section crowns each week's biggest win and luckiest hit by name.

    Pools

    Pools is not a table, and the house is not your opponent. Once a day the bot opens one market in its own channel and asks a single question: will the server economy grow by more than the line today? You back Over or Under, and everyone who backs the winning side splits the entire pool between them, in proportion to what they staked. Your winnings come from the people who called it wrong — which means the payout isn't a fixed multiplier. It depends on how the money ends up split, and it moves every time somebody bets.

    The panel shows the implied odds live: if 80% of the pool is on Over, the market is saying Over is 80% likely, and backing the unpopular side pays more precisely because fewer people are sharing it. It also carries a chart while betting is open — candlesticks of the economy itself with today's target marked, the daily swing beneath it, and the odds path tracking how the pool has moved through the day. Each candle is one day, and the body of today's candle is the number you're betting on. The result card repeats the candles with today's finally closed, so you can see how near it came.

    • The line is set by the bot, not by staff — it's the middle value of the last seven days, so it drifts with the server instead of needing anyone to keep it honest. It always ends in .5, so a day can never land exactly on it and there are no pushes.
    • Betting closes in the early evening (18:00 by default) but the day keeps running until midnight. That gap is the point: by closing time you can see how the day has gone, but the evening — where most of the swing comes from — is still unwritten.
    • Settlement isn't a judgement call. When the day rolls over the bot totals every coin created and destroyed and compares it to the line. There's nothing to dispute and nobody to appeal to.
    • If everyone picks the same side, nobody wins — there was no one to play against, so every stake is refunded in full.
    • A small takeout comes off the pool (5% by default) and is burned — destroyed, not paid to the house and not added to the jackpot. It's the one way Pools touches the economy at all.

    Winners get pinged on the result card, so you don't have to remember to check back.

    Bots and Metrics

    Every metric on the dashboard counts humans only. Bot messages — yours and third-party ones like Cat Bot, Gamebot, or DISBOARD — are left out of message volume, active-user counts, channel health, participation spread, sentiment, retention cohorts, and the newcomer funnel. A channel kept busy only by a bot therefore reads as quiet, which is the intent: it tells you what your members are actually doing.

    Command & Panel Usage Admin

    A dashboard panel (Reports → Bot Usage → Command & Panel Usage) showing which slash commands members actually run and which dashboard panels get opened — with counts, how many distinct people used each, error counts, busiest hours, and a daily trend.

    The part worth checking first is Never used, at the top: every registered slash command nobody has ever run, and every dashboard panel nobody has ever opened. That list is judged against all recorded history rather than the date range you've picked — a command last run three months ago is unpopular, not unused — which makes it a straight list of things you could retire.

    ℹ️
    What gets recorded

    For commands: the command name, who ran it, which channel, when, and whether it errored — not the options or text anyone typed into it. For the dashboard: one entry each time a panel is opened, not every background refresh, so the numbers reflect people rather than how long a tab was left open.

    Recording begins when this feature is installed; there's no backfill, so the report is empty until members start using the bot. Commands run in DMs aren't recorded, and neither are commands whose own error handler catches the failure — so the error count is a floor, not a total.

    Command usage is recorded for every member. Dashboard panel usage is recorded for mods and admins only — a regular member browsing their Wellness pages isn't tracked. Entries are kept indefinitely and are only ever cleared by a full data-erasure run — see Data Erasure. The report panel itself is admin-only.

    One-Sided Attention Mod

    A moderator-review report (dashboard sidebar → Reports → People → One-Sided Attention) that surfaces member pairs where one person keeps directing attention at another who isn't returning it. It's built to help you notice fixation or unwanted pursuit early — the shape of "A keeps showing up around B; B never seeks A out" — that's easy to miss message-by-message.

    It looks at three kinds of directed attention over a window you pick (default 30 days): replies & mentions, reactions, and voice-follows (joining a voice channel someone is already sitting in). A pair only shows up once there's enough back-and-forth volume to be meaningful and the attention is strongly one-directional — so two people who talked once, or a pair of mutual friends, won't clutter the list.

    Each flagged pair is presented as plain-language evidence chips — how one-sided it is, whether the other person ever responded, whether contact increased after they went quiet, how much of the initiator's attention is aimed at this one person, times they followed them into voice, and any rapid bursts. Where a reading has an innocent explanation, the report says so itself (a small friend circle, contact that's cooling off, or mostly-reactions that just read as ordinary support).

    ⚠️
    A tip, not a verdict

    This report never scores or ranks anyone behind a hidden number, and it never takes any action — it just points your attention at a pattern for you to judge as a human. It also doesn't use or infer gender. Treat a flag as "worth a glance," nothing more.

    Bots are automatically excluded, so a member who replies to or reacts to a bot never shows up here. Reactions and voice-follows are only counted from the day the feature went live onward (there's no backfill), so early reports lean on replies and mentions.

    20 Rules Watch

    A passive AI moderation monitor. Once enabled, Rules Watch screens every public message against your server rules and sorts anything suspicious into a tiered queue: immediate (an alert embed posted to your alert channel with Confirm / False-positive buttons), digest (queued for review in batches), and logged (recorded but not alerted). Labeling events as violations or false positives tunes the signal over time — the stats command shows your false-positive rate. Mods can also right-click any message → Apps → Report Rule Violation to hand-file it as a confirmed example the AI missed.

    ℹ️
    Requires the AI service, off by default

    Rules Watch uses the same local AI model as the AI Moderation Tools and does nothing until you turn it on from the web dashboard. Configure and review queued events on the dashboard's Rules Watch panel.

    ℹ️
    Configure via the web dashboard

    The Rules Watch config panel toggles monitoring on/off and sets which channel receives immediate-tier alerts (each alert includes the flagged message, the matched rule, and Confirm / False-positive buttons that keep working across bot restarts). The retired /rules-watch enable, /rules-watch disable, and /rules-watch set-channel commands are no longer needed.

    The Ledger

    The dashboard panel's Ledger tab is a separate thing from the alert queue, and it works differently on purpose. Where the queue holds the AI's opinion that a message might break a rule, the ledger records only that a specific, narrowly-defined thing was said. It makes no judgment, sends no alert, and has no Confirm / False-positive buttons — there is nothing to agree or disagree with. It exists so that if you are already reviewing someone, the relevant dates are on hand rather than reconstructed from memory.

    Two entries are recorded:

    • DM consent — someone says the consent bot is broken or that they don't know how to use it, and expresses intent to DM a particular person. Asking publicly before DMing is encouraged and never recorded; what lands here is the claim that the bot can't be used.
    • Cross-platform — someone shows they have already looked at another member's content on Reddit, Instagram, OnlyFans, Snapchat, Telegram or TikTok. Asking someone for their handle, or recognizing them from another platform, is ordinary and is not recorded — only demonstrating you went and looked. If the person raised that platform themselves in the last month, nothing is recorded.

    Both are deliberately rare — measured across fifteen months of server history they fire about once a month between them. If the ledger starts filling up, something has been widened and should be looked at.

    ℹ️
    The ledger runs even when the AI doesn't

    Unlike the alert queue, the ledger needs no AI model — it is plain text matching, so it keeps working if the AI service is unavailable. It still requires Rules Watch to be enabled.

    Rules Watch has no slash commands — reviewing and labeling all happen on the dashboard under Moderation → Rules Watch. The event list has tier filters (All / Immediate / Digest / Logged) and shows only unlabeled events by default, so the Digest filter is the batch-review queue. Each row carries ✅ Confirmed violation and ❌ False positive buttons, plus an optional Correct rule box — fill that in when the flag was a real violation but the guard matched it to the wrong rule; it's ignored if you dismiss the event instead. The Stats tab has signal firing rates, label counts, and the false-positive rate. Whether monitoring is on and which channel gets immediate alerts lives on Config → Rules Watch. The old /rules-watch digest, label, stats, and status commands were removed.

    The one Rules Watch action that stays in Discord is the Report Rule Violation message context menu — right-click a message → Apps → Report Rule Violation. It opens a short form (optional rule number and note) and logs the message as a confirmed violation straight away. Mod-only, and it refuses bot messages.

    21 Todo List & Board

    A shared worklist for the mod team. Tasks can be added from Discord or from the dashboard, and everything lands in the same list. It is moderator-only end to end — members never see it unless you post the board in a channel they can read.

    The Discord board

    The board is a single message the bot keeps at the bottom of a channel. It lists every pending task oldest-first, so whatever has been waiting longest sits at the top. It carries two buttons:

    • ➕ Add Task — opens a small form for the task and optional notes.
    • ✅ Complete — shows a private picker of pending tasks; tick one or several off at once.

    Both buttons are moderator-only. Anyone else who clicks gets a private "moderators only" reply and nothing changes.

    The board updates itself. Adding or completing a task anywhere — the buttons, /todo, or the dashboard — is reflected within about a minute, and immediately when the action came from Discord. When people chat in the channel, the board deletes itself and re-posts underneath so it never scrolls out of sight. Tasks marked 🔁 came from a recurring entry.

    ℹ️
    Posted from the web dashboard

    Pick a channel on the Todo List panel and press Post Board. Posting or moving the board is an administrator action; managing the tasks and recurring entries on it only needs moderator. Removing the board deletes the message but keeps every task.

    Recurring tasks

    Recurring entries put a chore on the list on a schedule — "Post QOTD" every morning at 09:00, "Photo challenge prompt" every Monday. Set them up on the dashboard panel with a daily or weekly cadence and a time of day (server local time).

    These are reminders, not automation. When one comes due the bot adds the task to the list; a moderator then does the thing and ticks it off. The bot does not post the QOTD or the photo prompt for you.

    If the previous copy of a recurring task is still sitting on the list, no duplicate is added — a chore nobody got to all week shows up as one increasingly old task rather than seven identical ones. Each entry can be paused, edited, deleted, or fired immediately with Run now — which adds one instance there and then without touching the schedule or un-pausing a paused entry. Deleting an entry stops it repeating but leaves any copy already on the list, since that is real outstanding work.

    Inactive Members

    A softer sibling of the jail system for idle members: instead of a per-user cell, everyone held inactive shares one channel. Roles are snapshotted and stripped, the member gets an @Inactive role that can only see that channel, and a persistent panel there lets them open a ticket to be reactivated.     /inactive release user:@member [reason] Mod — Moderate Members Restore whichever snapshotted roles still exist and remove @Inactive.

    Sweeps also run from Config → Inactive Sweep. Check Now is a dry run — it lists members idle past the threshold without touching anyone. Move Them Now moves exactly those members through the same mark flow, and tells you how many a single run reached if the per-run cap held some back.

    ℹ️
    Configure via the web dashboard

    The Inactive Sweep panel sets the idle-day threshold, the per-run cap, and whether the sweep also runs automatically every 6 hours. The retired /inactive config command is no longer needed.

    Who Would Be Swept Right Now — press Check Now for a dry run against the settings on the page (including a threshold you have typed but not saved). It lists every eligible member, most idle first, with the roles each would lose; click the role count to see them by name. Nothing is moved and no roles change. Because it selects through exactly the same code the real sweep uses, the listing is what a sweep would actually do — with three things called out that the sweep itself never says out loud:

    • the per-run cap, so you can see how many of the listed members one run would actually reach and how many wait for the next;
    • Would Fail — Bot Outranked, members holding a role the sweep would strip that sits at or above the bot's own role. A sweep picks them up and then silently fails to strip them; move the bot's role above theirs to fix it. Roles managed by an integration (booster, Twitch, another bot) don't count here — the sweep never touches them, so they don't block the rest;
    • no tracked messages, shown in place of a last-seen date for members with no message history at all. They are aged from their join date alone, so a long-standing member who was active before the bot started tracking looks identical to one who never spoke.

    Never Sweep These Members — exempt individual members from inactivity holds. An exemption is absolute: both sweeps skip them, and /inactive mark refuses them, so it can't be undone by accident from Discord. Bots, the owner, admins and moderators are already protected and don't need listing. You can exempt someone straight from a preview row with Never Sweep.

    Bump Reminders

    Tracks server-listing sites (e.g. DISBOARD) and reminds you when a bump cooldown has expired, with a status widget pinned to the bottom of the configured channel. Bumps are auto-detected from the listing bot's confirmation message where supported.

    The reminder channel, ping role, tracked sites, and auto-detection rules are configured on the Bump Tracker panel in the web dashboard.

    Each site's Detection settings decide how a bump is spotted automatically:

    • Bot ID — the listing bot's user ID. Set it and bumps are recorded without anyone running /bump log.
    • Text when bumped — only count messages containing this phrase (e.g. Bump done!). Leave blank to count any message from that bot.

    Intake Cards

    Turns your welcome procedure into a live checklist. When someone joins, the bot posts an intake card to greeter chat — pinging the greeter role instead of the old bare @here line — showing a progress bar, the member's account age, who invited them, and the procedure as ✅/⬜ steps. The card is a tracker, not a control panel: welcomers keep greeting, asking the question lists, and running /grant exactly as before, and the card ticks itself — a greeter or mod mentioning or replying to the newcomer in your greeter chat (or welcome) channel ticks Greeted, passing verification ticks Verified, and gaining a configured role (via /grant or a manual add) ticks the matching role step. The question phases are buttons welcomers tick by hand. Nothing anyone says is ever recorded — only that steps happened, by whom, and when.

    Two of those auto-ticks depend on settings elsewhere, and the panel tells you which channel and role it is watching. Greeted watches the channel newcomers are actually talked to in — your greeter chat channel, or the welcome channel when that isn't set, both on Welcome & Leave. It is not the card channel: the card is the bot's noticeboard, and a greeting posted there isn't the greeting the newcomer sees. Verified accepts either shape verification takes — your unverified role being removed, or a Verified role being granted by a verification bot such as Double Counter. If yours only grants a role, pick it in the Verified role box on the Intake panel, or that step can never tick.

    Steps can also tick themselves from what you paste. Give a step a step code — any phrase you like — and drop that phrase into the canned message for that stage of the procedure. When a greeter or mod posts it while @mentioning or replying to the newcomer, from any channel, that one step ticks and the card stays open. So pasting your "we're done with the SFW portion" message ticks the SFW step by itself, with nobody touching the card. A -# subtext line is a tidy place to park the code. Codes are matched anywhere in the message and ignore capitalisation, so no code may contain another one, and none may contain the completion code — the dashboard refuses the save and tells you which two clash.

    To finish an intake, the welcomer posts the ending welcome message containing the configured completion code and @mentioning (or replying to) the newcomer — any channel works. The card completes, the poster is recorded as the welcomer, and any unticked steps are marked skipped (visible in analytics, never blocking). Cards only ever close on completion, a mod's Dismiss, or the member leaving or being banned — so the open cards are your intake queue. A card with no progress for the configured window gets one greeter-role nudge reply, never more.

    When the Economy is running, greeters earn coins for the intake work itself: each checklist step pays a flat award to whoever ticks it — by the card's buttons, by the greeting that ticks Greeted, or by pasting a message carrying that step's code. It pays per step rather than per finished card on purpose — when two people share a welcome, each is paid for what they actually did, instead of the whole award going to whoever happened to post the completion code. A step pays once per card, so unticking a step and ticking it again is worth nothing, and a second greeter can't re-claim a step someone already ticked. Steps that tick themselves from a role change (Verified, the role grants) have no person behind them and pay nobody, and skipped steps pay nothing — only work that was actually done earns. The rate lives on Economy → Income Sources ("Ticking a step on a newcomer's intake card"), where the whole source can also be switched off; an optional intake_step quest in Economy → Quests stacks a bonus on top.

    The panel also manages a procedure reference channel (your #welcome-procedure): the text sections and question lists live in a block editor on the dashboard and the bot keeps the channel in sync. Every block's heading posts as its own message and the content below it as another, so Copy Text on the content gives you exactly the text to paste with no heading to trim; question lists go a step further and post one message per question. Rewording a question edits the same message in place (links keep working); a one-time Import button seeds the editor from the channel's existing content. The bot never touches messages humans posted there.

    If someone deletes one of those messages in Discord, the next Save & sync channel puts it back — you don't have to change the text first. Because Discord can only add messages at the bottom, restoring one means re-sending everything below it so the procedure still reads top to bottom; the messages above it are left alone. The status line tells you how many were restored.

    ℹ️
    Configure via the web dashboard

    Chat Revive

    Notices when a channel has gone unusually quiet for that channel, at that time of day, and gently restarts conversation by posting a question card from a curated bank — optionally tagging an opt-in chat-revive role. It's not a timer bot: it learns each channel's rhythm, never talks over an active room, never posts twice in a row, and strict frequency protections (per-channel rest period, guild daily budget, quiet hours, at most one ping per channel per day) keep it rare enough to feel like a treat. Spicier questions only ever surface in age-restricted channels. Members join or leave the ping role through the server's usual self-role flow; there are no slash commands.

    ℹ️
    Configure via the web dashboard

    The Chat Revive panel covers eligible channels and their question flavors, the ping role, quiet hours and budgets, the question bank (add, bulk-import, retire), a "would it fire right now?" explainer per channel, a manual Fire button, posting the opt-in button, and a scoreboard of which questions actually spark conversation.

    Event Echo

    Posts a small note in main chat whenever something worth your attention is happening elsewhere in the server, with a link that takes you straight to it — so a game running in the games channel doesn't go unnoticed by everyone sitting in the main room. Two kinds of note: something just started (a party game opening for players, including ones the scheduler launches by itself; a Cards Against Humanity game in the tracked Gamebot channel; a Discord server event going live; a new bounty posted), and last chance (an auction closing within the hour, a prediction-market round whose betting is about to shut, or the weekly raffle an hour before ticket sales close — that one links straight to the shop's buy button).

    It never pings. Echoes are silent by design: no role is tagged and nobody is notified — the note is there for people already reading the channel. Results are never echoed, only things you can still act on, so the link is always worth clicking. Rate limits keep it rare: the same kind of game at most once an hour, and nothing at all within ten minutes of the previous echo; anything arriving inside those windows is skipped rather than announced late. Last-chance notes are the exception — they happen a few times a year and there's no later moment to retry them, so they always get through, but still only once each. There are no slash commands.

    ℹ️
    Configure via the web dashboard

    The Event Echo panel has one setting: which channel echoes are posted in. Leaving it on "(off)" disables the feature entirely.

    Hidden Channels

    Hide a channel from everyone and later restore it exactly as it was. Hiding snapshots the channel's permission overwrites and placement, then parks it under a "Hidden Channels" category with @everyone denied View Channel (members with Administrator still see it — Discord always exempts them). Restoring moves it home and reinstates the original overwrites. Hides last until restored — there's no scheduled auto-restore.

The bot needs Manage Channels and Manage Roles. No dashboard panel — these three commands are the entire interface.

    24 Content & Comms

    Bot-maintained content and outbound messaging: self-assign role menus, dashboard-authored documents posted into channels, and scheduled announcements. All three are built on the dashboard and post persistent messages that keep working across bot restarts.

    Role Menus

    Self-assign role menus, built entirely on the dashboard and posted into a channel as a persistent message with buttons or a dropdown. Members click to manage their own roles — the reply is only ever visible to them — and the message keeps working across bot restarts. Each menu has one of five modes:

    • Toggle — click to get the role, click again to drop it.
    • Unique — only ever one role from the menu at a time (picking a new one swaps it).
    • Verify — gain-only, for verification gates.
    • Drop — remove-only, an opt-out station.
    • Binding — the first pick is permanent, one ever per member.

    There are no slash commands — members just click the posted message.

    ℹ️
    Configure via the web dashboard

    The Role Menus panel is where you build a menu (roles, labels, emoji, mode, button vs. dropdown), pick its channel, and post or re-sync the live message. For a quick role button attached to a one-off post, see Announcements instead.

    Docs

    Author documents on the dashboard and post them into channels as bot-maintained messages — rules pages, guides, FAQ posts. Edit the doc on the dashboard and re-sync; the posted copies update in place.

    Docs have no slash commands — everything is on the dashboard's Docs panel. Write the document there, then use its placement controls to post it into a channel (which keeps it synced), sync it to re-render every copy in place, pin or unpin a placement, or remove it from a channel. The panel also lists every doc and where each is posted. The old /docs post, sync, unpost, and list commands were removed.

    Announcements

    Queue server announcements on the dashboard, preview them, and set a post time — the bot posts them for you. Each announcement is a rich embed (title, markdown body, optional image, accent color that defaults to your server branding) plus an optional plain-text line shown above the embed. Mentions only ping from that plain-text line, and only when you explicitly pick them: no mentions, one role, or @everyone — nothing pings by accident. Times are server-local (the timezone offset from the Global config panel).

    ℹ️
    Manage via the web dashboard

    The Announcements panel (admin-only) has the queue, a live Discord-style preview while you type, and a Sent history. Save without a time to keep a draft; add a date and time to schedule it. Post Now sends within a minute. Sent items keep an "Open in Discord" jump link and can be cloned back into a fresh draft. If the bot was offline at post time it still posts up to 2 hours late; past that the item is marked as missed instead of posting stale news — clone and reschedule it.

    Role Buttons

    An announcement can carry up to five role buttons. A member clicks one to give themselves that role and clicks again to drop it — the reply is only ever visible to them. Handy for opt-in pings, event signups, and notification roles: post the announcement once and the button keeps working from then on, including after the bot restarts and even if you later delete the announcement from the queue.

    Give each button a role, and optionally a label (blank uses the role's own name, so renaming the role renames the button), an emoji, and a color. Leave the button list empty for a plain announcement.

    ⚠️
    Roles with mod powers can't go on a button

    Any role carrying Administrator, Manage Server / Roles / Channels / Messages / Webhooks, Kick, Ban, Timeout, or Mention Everyone is refused, as is any role above Dungeon Keeper in the role list. Unlike Role Menus there's no override — an announcement is public and stays clickable forever, so this one is a hard no. The check runs again on every click, so if a role picks up mod permissions later, the old button stops handing it out on its own. Members who already have the role can always still remove it.

    27 QA Tracker

    A volunteer testing crew for the bot itself. Each new change lands as a QA card in the testing channel — an embed carrying the test checklist with Pass / Fail / Blocked buttons. Members holding the configured QA-crew role click a verdict (Fail requires a "what went wrong" note, which lands in the card's thread); the first Pass turns the card green as verified. Your first verdict on a test pays economy currency instantly, up to a daily cap — re-clicking updates your verdict without re-paying. Until an admin configures the QA-crew role, the buttons are admins-only. A card that's stayed verified (green) for 10 minutes is automatically deleted from the channel to keep the queue tidy — the verdicts and payouts stay on record, just the message goes.

    ℹ️
    Admin oversight on the web dashboard

    The Dev-section QA Tracker panel (admin-only) has the status board with every test and its verdicts, a top-testers scoreboard, and the config knobs: QA-crew role, channel, reward amount, daily cap, and enable toggle. A bogus verdict can be voided there — the paid coins are clawed back and the card's status recomputes. Archiving retires a card.
