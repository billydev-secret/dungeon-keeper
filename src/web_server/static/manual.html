    1 Getting Started

    Dungeon Keeper is a Discord companion — moderation, XP, voice, music, games, wellness — plus a web dashboard for settings and reports. Commands do things; the dashboard holds every setting. Permissions are tagged Everyone Mod Admin Bot Owner — see Permission Levels. Search above, or browse the Quick Reference.

    I'm setting up the server

    1. Sign in to the dashboard and work through First-Time Setup.
    2. Skim the Feature Map below and enable what you need.

    Finding a Page on the Dashboard

    There are a lot of panels, so don't hunt the sidebar. Press Ctrl+K (⌘+K on a Mac) anywhere in the dashboard and type: you get a flat list of every page you can open, each labelled with the section it lives in, plus matching headings from this guide. Arrow keys move, Enter opens, Esc closes. The sidebar's own filter box still works the same way if you prefer it. If you're wondering where a feature's settings are, see Where a Setting Lives.

    Ask Billy-bot (AI)

    Run /ask, or use the Ask Billy-bot box above — a guide-grounded AI that won't invent commands. Admins get more from Config → AI Assistant: model per audience, live server context, a setup review, and Apply buttons for settings changes. Details in Configuration.

    Posting an answer to the channel (mods). Set public to True on /ask and the answer comes back written as a short public tutorial — a line of setup and a few numbered steps, aimed at the whole room rather than at you. You see it first, privately, with a Post to channel button: press it and it goes into the channel you ran the command in, exactly as previewed, with your name on it; press Discard and nobody else ever sees it. A public answer is deliberately written with less to work from than a private one — only what everyone in the server can see, and never your settings, so it can't repeat something from a staff channel or a config panel to the room. Ordinary members can still run /ask; only mods get the public option.

    Live server context is off until an admin switches it on. With it on, each question is answered using the shared channels you can see (names and topics), server docs, recent announcements, and your roles — never a channel you can't see, and never an age-gated one. Private per-member rooms (jail, tickets, Pen Pals, the bios wizard) are left out entirely, for everyone including staff: those channels are named after the people in them. That material goes to the AI along with your question — it is the one part of the bot that sends anything off the server, so see Privacy & Your Data.

    It is never given anything about a member — not your bio, birthday, confessions, wellness entries, DMs, balance, inventory or stats, and not anyone else's, whether or not live server context is switched on. It isn't given messages people have posted either. Ask it what someone's bio says and it will tell you it has no access and point you at the bios channel; if it ever appears to answer such a question, it is making the answer up, so please report it to a mod. Your roles go to it because answers are tailored to what you're able to do; your nickname does not.

    ℹ️
    Billy-bot never changes a setting on its own

    When an admin asks it to set something up, it proposes the change: the reply lists each pending change in full — the setting, and the exact value it would write — and nothing happens until an admin presses Apply. Read the listed change rather than the button, which shortens to fit. Your permissions are checked again at the moment you press it, and settings that hand out access, or that route private material to a channel (the whisper mod log, ticket and jail transcripts), need a full server administrator. Billy-bot is deliberately not allowed to touch admin or mod roles, message retention, or to put an @everyone in a grant message.

    3 Games Night

    A suite of party games, duels, and group elimination games for hangouts and game nights. Everything is member-facing — anyone can start a game in an allowed channel. Only one game runs per channel at a time. Type /games help in Discord for the in-app version of this list.

    💡
    Channel allowlist & NSFW

    Games only run in channels an admin has allowlisted on the Games Config panel in the web dashboard. Spicier (NSFW) prompts are served only in channels marked age-restricted in Discord; every other channel stays SFW.

    Party Games

    All start with /games play <mode>, Everyone in allowed channels. Most run in rounds: a host starts the game, players join or vote with buttons, and the host advances rounds. Prompts come from the question bank — see For hosts & admins.

Every meter is the same length whatever the split, so you can compare options at a glance — the same meter style is used for quest and community-goal progress, the casino's implied-odds bar, and the Chicken and Pressure Cooker gauges.

    ⏰
    Give people time to show up: start_in:

    Six games open a lobby and wait for you to press start — Clapback, Spin the Compliment, Marry, Fornicate, Kiss, Most Likely To, Mt. Rushmore Draft and Story Builder. Add start_in: (1–60 minutes) when you open one and the lobby shows a live countdown, so people know when to be there — e.g. /games play rushmore start_in:15.

    The game does not start by itself. When the countdown runs out the bot posts a message in the channel tagging you, so you don't have to watch the clock — you still press the button when everyone's in. Most games that aren't on that list begin the moment you run the command, so they have no start_in:.

    Scheduled games work the same way: if an admin has one of those six on a schedule, the bot tags whoever set it up as soon as the lobby appears, since someone still has to start it.

    A schedule can also be set to announce when it starts — the bot posts a note in the channel (pinging a role, if staff picked one) the moment the game goes up, with a link straight to it. The note follows the game rather than leading it, so it never announces one that failed to appear.

    Two Truths and a Lie, Hot Takes and LegitLibs also wait on the host, but don't take start_in: yet.

    If your server runs a quest like Ask in an AMA, the payout stays off the server's transaction feed, and such a quest can't be set to require staff sign-off. AMA questions post anonymously, so anything naming you seconds after one appeared — a payout entry, or a sign-off waiting in a staff channel — would give you away by timing alone. You still get paid: the credit shows on your own /quests board and /bank wallet ledger. Answering questions in your own AMA is not treated this way — the hot seat is public.

    🏷️
    Nickname stakes & staff

    By default the loser surrenders their nickname for a set sentence, so the bot needs the Manage Nicknames permission — without it these games can't run. A player whose top role sits above the bot's (a staff member, say) can still play: the game shows a heads-up that it won't be able to rename them, and if they lose the win still counts — the winner's chosen name is posted in the channel and it's on the honour system. To let the bot rename them too, move its role above theirs in Server Settings → Roles.

    The server owner can never be renamed by anyone — that's a Discord rule, not a bot setting. Challenges involving the owner say so up front, and if the owner loses, the bot posts the nickname and the owner applies it themselves.

    🎲
    Stacking stakes

    A challenge can carry up to three things at once, and they're independent: coins (wager:), something you write yourself (stakes:, honour-based — the bot just announces it), and the nickname forfeit (nickname:). Leave nickname: alone and it's on when you've staked nothing else and off when you have, so a bare challenge works exactly as it always did — but set nickname: True alongside a wager and the winner takes the pot and gets to rename the loser. Every stake you set is listed on the challenge, during the game, and on the result, so nobody finds out about one of them at the end.

    💰
    Coin wagers

    All six duel and group games take an optional wager: amount — every player antes the same, and the winner takes the pot. Some servers set a small house cut on won pots; when one applies, the payout message says exactly how much the house kept. Refunds are never cut. In a 1-v-1 challenge nothing is charged until the target accepts (declining or letting it time out costs nothing); in a lobby game you pay as you join, and leaving the lobby refunds you. If a game is abandoned, voided, canceled, or ends with no winner, every stake is returned — and if you leave the server mid-game your stake comes back automatically. Wagers need the economy enabled and use your /bank wallet balance.

    For Hosts & Admins

    /games config game-status    /games end force:true Mod Show the active game in the current channel, or force-close it if it's stuck. The games channel allowlist and the audit log channel are managed on Games → Operations → Global Config in the web dashboard. To stop recording game events, choose (none) in the Audit Channel picker and press Save — nothing is logged from then on, and messages already logged are left alone.

    External game tracking lives on the dashboard under Games → External Tracking — it replaced the /games track commands. The bot watches a channel where another game bot (Gamebot's Cards Against Humanity, Connect 4 and Anagrams; Cat Bot; Wordle; Co-ordle) posts results, and pays economy rewards for wins and catches. Wordle pays out on the daily group digest — solving in fewer guesses earns more, and everyone tied for 👑 gets the win bonus. Co-ordle pays each round once it's solved or runs out of rows, splitting by the points each player earned. Cards Against Humanity pays on the final scores, scaled by the points each player took; a game Gamebot drops part-way still pays for the rounds that were played, and if that leaves the lead tied, every tied player gets the win bonus.

    Cat Bot catches pay by rarity, and each of the six tiers is a rate on Economy → Income Sources. Beside them sits Cat Bot catch — per-member daily cap: leave it at 0 for no limit, or set a ceiling and each member stops earning coins from catches once they reach it that day, resetting at the next server-local midnight. Catching is a volume faucet, so the cap is the dial that cools a heavy catcher without touching everyone else. A member who has hit the cap still catches normally and their cat quests still tick — only the coins stop.

    On the panel: add a watch by picking a channel, the game bot, and the format. Add one per channel to track a bot that plays in several — games running in different channels at the same time each pay out on their own. Each row shows how many messages it has banked, with Pause/Resume (data is kept while paused) and Sample, which dumps that bot's recent messages so you can confirm the format parses before trusting the payouts.

    4 Photo Challenge

    A standalone scheduled photo feature (it used to live in the Games suite). On its configured schedule the bot posts a photo-prompt card to a dedicated Photo Challenge channel, optionally pinging a role. Members answer by posting their photos in that same channel — no commands involved.

    💡
    Posting is the reward

    When the Economy is running, simply posting an image in the Photo Challenge channel pays out a flat participation award — no reactions or replies needed. If there's also an active photo_post quest, its reward stacks on top of the participation award. Both are capped at once per member per day, no matter how many photos you post.

    ℹ️
    Configure via the web dashboard

    Admins (or the game-host role) set the channel, ping role, recurring schedule, and enabled toggle on the Photo Challenge → Setup & Schedule panel. The flat participation award is a faucet rate on Economy → Income Sources ("Photo Challenge post"); the optional stacking bonus is a photo_post quest in Economy → Quests. The prompt bank lives on that same panel. The old /games play photo command is retired.

    7 Confessions

    Anonymous Confessions

    The confessions system lets members post anonymously to a configured channel. Confessions themselves carry no identifier at all. Anyone replying in a confession's thread gets a colored emoji and nickname (e.g. 🔴 Brave Owl) that stays consistent within that thread so a conversation is followable — everyone sees it, and it says nothing about who the person is. To put a real name to a confession or reply, mods use the admin-only Confessions Audit Log.

    /confess Everyone Opens an anonymous submission modal (up to 4,000 characters). The confession is posted to the confessions channel with no identifier attached, and seeded with a reply bar so others can respond anonymously.
    ℹ️
    Mod capabilities in confessions

    Mods can see who is really behind every confession and anonymous reply on the Confessions Audit Log panel, block a specific member from confessing (without revealing their identity), and enable panic mode to temporarily suspend all new confessions.

    The audit panel is admin-only and needs no setup. You can also point confessions at a mod-log channel in Discord, but it's optional and off by default — anyone who can read that channel can put a name to every confession in it, so the dashboard is the safer place to review them.

    🤫
    Confession quests pay you quietly

    Quests for posting a confession or replying to one are paid without any public trace — no transaction-feed entry, and such a quest can't be set to require staff sign-off either — both would name you seconds after the anonymous post appeared. The credit still lands, and shows on your own /quests board and /bank wallet ledger.

    8 Pen Pals

    Pen Pals quietly matches members into private one-on-one conversations. However you're matched, the bot spins up a private two-person channel, seeds it with a conversation-starter question, and tears it down again after a configurable session length (default 24 hours).

    How you're matched

    The server's Pairing Mode, set on the dashboard, decides when:

    • Instant — you're matched straight away if someone eligible is already waiting; otherwise you sit in the pool and are matched the moment the next person joins.
    • Once a day — never matches on join. Everyone who joins queues up, and the whole pool is paired in one batch at 8:00 AM Eastern.

    Who you won't be matched with

    • The same person twice — once two members have been pen pals, Pen Pals won't put them together again. If everyone waiting is someone you've already had, you simply stay in the pool until a new face joins.
    • Anyone you've blocked — /penpals block keeps the two of you apart, privately, and one block is enough.
    • More than one person at a time — nobody is ever in two pen pal chats at once, and after a chat ends there's a re-match cooldown (set on the dashboard) before you can be paired again.

    Taking a break

    Whenever you've had enough — waiting in the pool, or right in the middle of a chat — press Leave Pool on the signup panel, run /penpals leave, or use the Leave the pool button in a closing DM. They all do the same thing, and it sticks: you won't be matched again, and you won't be put back in the pool when a chat of yours ends. It stays that way until you decide otherwise — nothing expires it, and nobody else can undo it for you.

    Leaving mid-chat doesn't end the conversation you're already in — it runs to its normal finish, and your pen pal is never told. (To close a chat early, that's /penpals end.) It only decides what happens afterwards, and /penpals status will remind you it's set.

    Coming back is one press of Join Pool or /penpals join — that clears it, even if you're still in a chat at the time.

    When your chat ends

    You'll get a DM the moment it closes, and what it says depends on whether you used the chat:

    • If you posted in it — you go straight back into the pool for a new match, and the DM says so. If you'd rather stop there, the Leave the pool button in that DM takes you out and keeps you out (see Taking a break above); /penpals leave and the panel's Leave Pool button do the same.
    • If you never posted — you're quietly taken out of the pool instead, so your spot goes to someone who's ready to chat. Nothing is held against you: the DM has a Join the pool button, and you can hop back in whenever you feel like it.

    Going back in the pool doesn't mean you'll be matched immediately — the re-match cooldown still has to pass first, so there's always a breather between chats.

    10 Meadow Mahjong

    Card-driven American-style mahjong, played entirely in Discord with real coin stakes. You win a hand by matching your fourteen tiles, tile for tile, to one of the hands on the season’s Meadow Card — an original set of patterns that rotates with the seasons. Open your panel with /mahjong: it shows the card in season, the allowed stakes, and your balance, with buttons to open a table, study the card, check your record, set how much help you want, and — if any of this is new — a How to Play summary of a whole hand from sitting down to declaring Mahjong.

    Sitting down

    • Two table sizes. A Duel seats two; a Full Table seats four. Pick a size and a stake (coins per point) and the table card posts in the channel for others to join — one table per channel, one seat per player.
    • Escrow locks when you sit. The most a hand could possibly cost is set aside from your balance when you take a seat, and every coin you don’t lose comes back when the hand settles. If you can’t cover the escrow, the seat refuses politely.
    • The table card keeps itself at the bottom of the channel — chat above it and it re-posts underneath. Your tiles stay private: press Open Rack on the table card any time for your own view, with whatever buttons the moment calls for.

    The Charleston

    Before play, everyone passes tiles: three passes of exactly three (jokers never pass), then a vote on an optional second round — it runs only if everyone says yes — then a courtesy exchange where each side offers 0–3 and trades the smaller number. On the final pass of each round you can pass blind: mark slots to forward tiles from the ones arriving, sight unseen.

    Playing a hand

    • Draw, then discard. On your turn a tile is drawn for you; pick one to throw. Take too long and the drawn tile goes by itself — three timeouts in a row folds your seat (it still pays the winner, so stay at the table).
    • Jokers are the engine. A standard wall holds eight, but your server can deal more — more jokers means hands actually finish instead of the wall running dry, and games end sooner. Ask an admin if a night keeps ending in wall games.
    • Quick tables. If your server has switched them on, opening a game offers Quick Duel and Quick Table alongside the usual sizes. A quick table plays with only the low numbers — 1–5 or 1–6, whichever the server picked — and every suit and honour tile is still there. Fewer tiles means the ones your hand wants turn up sooner, so a hand runs roughly half as long without anyone winning less often. The table card says Quick and the range, so you always know which game you sat down to. Any hand on the card that needs a number above the limit simply can’t be made that game.
    • Every discard opens a claim window. Anyone else can press 🀄 Mahjong (it completes their hand), ✋ Call (they expose a matching set of three or more), or Pass. Mahjong beats a call; a call beats waiting your turn. Pairs can’t be called — only the winning tile breaks that rule. If you hold nothing that could take the tile, the table doesn’t wait on you — your pass is entered for you and the window moves straight on, so a hand isn’t spent waiting for decisions nobody could make. You can still tap Pass; it just won’t tell you off.
    • Jokers stand in for anything inside sets of three or more — never in pairs. If someone’s exposure holds a joker and you hold the real tile it’s impersonating, you can swap for it on your own turn.
    • A wrong Mahjong costs nothing and shows no one. Press it whenever you believe; if the fourteen don’t match a line, only you find out, and your press quietly becomes a Pass.
    • Hands marked C on the card must stay concealed — no calling; they can still win by claiming the finishing discard.

    Payouts

    Every hand on the card has a point value, and the stake turns points into coins. Winning off someone’s discard makes the thrower pay double their share; drawing your own winning tile (self-pick) pays more still; winning with no jokers in your fourteen doubles everything. If the wall runs dry with nobody out, nothing changes hands. After the settle, a unanimous Rematch deals again with the dealer passing along one seat.

    Study the card

    Wherever you pick tiles — passing in the Charleston, giving courtesy tiles, discarding, exposing a call — the menu shows the tile faces themselves, so you are choosing pictures rather than codes.

    Your rack panel keeps itself up to date: once you open it, it follows the game — new draws, the claim window, whose turn it is — for about fifteen minutes, after which Discord retires it and one press of Open Rack gets you a fresh one.

    The Card Viewer button on /mahjong shows every hand in season, section by section, with its pattern, point value, and whether it must stay concealed. The season card is also on the dashboard for reading outside Discord.

    Assistance — how much help the table gives you

    Open My Settings on /mahjong and pick your level. It applies to every game you play on the server, and only you see your readout:

    • Off — pure card-reading, nothing extra.
    • Target — your rack panel names the hands closest to what you hold and how many tiles away each one is. “Closest” weighs how a tile can actually reach you, not just how many you’re short: a tile missing from a set of three or more can be drawn, called off a discard, or covered by a joker, while one missing from a pair can only be drawn. So a hand of pairs that looks two tiles away is ranked behind a hand of kongs that looks four away — because it is genuinely further from finishing.
    • Target + gap — also lists the exact tiles you still need for each.
    • Coach — narrows to your single closest hand, then points out the tiles it can’t use and suggests a discard. When someone discards, it also tells you whether that tile is worth taking — that it wins the hand outright, or that calling it would expose a set and bring you closer, or nothing at all when letting it go is right. The coach stays quiet rather than suggest a tile another player’s exposed sets say they might want — so no suggestion sometimes is the advice.

    Fair warning: right after the deal everything is far away and the readout is mostly noise — it earns its keep mid-hand, once discards and exposures thin the card. Players at one table can be on different levels; if your server prefers a house norm, admins set the default level on the dashboard, and your own pick always wins.

    Playing with bots

    Two ways the house 🌱 bots can join, where your server has them switched on:

    • Practice tables — pick 🌱 Practice Duel or 🌱 Practice Table when creating. You play alone against bots, completely free: no stakes, no stats, no results — the table itself is the only trace kept, same as any game. The perfect place to learn the card (and to see what the assistance levels do).
    • Filling a real table — short a fourth? The host can press Add Bot in the lobby to seat a house bot at full stakes. The bot’s coins are the house’s, not conjured — when you beat it you are genuinely paid, and when it wins the pot genuinely goes. Bots are always named with a 🌱 so you can never mistake one for a person.

    Bots play a solid, honest game off the same reading of the card the Coach assistance level shows you — they never see your tiles, only what everyone can see on the table.

The casino's name (shown here as "Golden Meadow", the default) is per-server branding, set on Config → Branding.

    The tables

    • 🪙 Coinflip — call heads or tails, pick an amount. A win pays 1.85× your bet.
    • 🎰 Slots — three spinning reels. Any pair pays 1.45×, triples pay 6–40× — and triple 7️⃣ wins the progressive jackpot: a share of every lost bet (on any table) feeds a pot shown on the casino panel, the lucky spinner takes the whole thing (never less than the flat 120×), and the pot reseeds for the next dreamer.
    • 🃏 Blackjack — hit, stand, or double down against the dealer. Dealer stands on 17; a natural blackjack pays 3:2. Wander off and your hand stands itself; if the bot restarts mid-hand, your bet comes back.
    • 🎡 Roulette — your own European wheel. Bet red/black (2×), a dozen (3×), or a single number (36×), stack as many bets as you like, then press 🎡 Spin when you're ready.
    • 🏇 Derby — six meadow critters to the starting gate, and they're yours. Back as many runners as you like with a button — the favorite 🐇 pays 2.5×, the longshot 🐌 pays 12× — then press 🏇 Race and the finish plays out on your own card.
    • 🎴 Baccarat — your own coup. Back the Player or the Banker (both pay 2× — the best odds in the house; ties hand your bet back, and a Banker win on a three-card seven pushes instead of paying) or the long-shot Tie at 9×. Press 🎴 Deal and the cards fall by baccarat's fixed drawing rules — no decisions, nearest to nine wins.
    • 🎲 Dice — three dice, your roll. Call Big (11–17), Small (4–10), Odd, or Even — all pay 2×, but any triple sweeps the table for the house. Make your calls, then press 🎲 Roll.
    • ⚔️ War — the fastest table in the house: one card each, aces high, the higher card pays 2× on the spot. Matched cards are a standoff — Go to War (double your stake; win or tie the next card for 3× your original bet) or Retreat with half. Going to war is always the better play, and if you wander off mid-standoff the house goes to war for you (or retreats if you can't cover the raise).
    • 💣 Mines — twenty tiles, and you choose how dangerous: 1, 3, 5 or 10 bombs. Every safe tile you open lifts your multiplier, and you can Cash Out at any moment — the button always shows exactly what you'd walk away with. Hit a bomb and the grid takes the lot. Whichever risk you pick, the ladder tops out at much the same place — between 18.6× and 21.9× — and cashes you out there, so the choice is how long the road is (19 nervous tiles on one bomb, four brutal ones on ten), not how big the prize gets. Open nothing and change your mind? Walk away and your bet comes straight back; wander off mid-grid and the house cashes you out at the multiplier you reached, never less. Returns ~95% at every single stopping point — there is no "wrong" moment to stop.
    • 🔢 Keno — your own draw. Grab a quick-pick ticket of 4, 6, 8, or 10 numbers (the house picks them — fate does the rest), press 🔢 Draw, and 20 of 80 numbers drop; pays scale with how many of yours hit: catch everything on a big ticket and the multipliers run into the thousands. Tuned far kinder than real-casino keno (~95% return). The result card shows every ticket — winners and losers alike — with your numbers that hit in bold and how many you caught, and an unpaid ticket also says how many it needed, so a near miss is never a mystery.

    The payout tables are fixed and published on the panel's How It Works button — the house keeps a few percent on every table, so treat it as entertainment, not investment. Admins set minimum/maximum bets and a daily wager cap per member; when you hit the cap, the tables politely refuse you until the next server day.

    The tables have a sense of occasion: big bets get the show (reels stopping one by one, the dealer pausing on the hole card, the roulette ball bouncing before it lands), wins of 10× or better go gold, and hot or cold streaks of three-plus get called out on your results.

    Pools

    Pools is not a table, and the house is not your opponent. Once a day the bot opens one market in its own channel and asks a single question: will the server do more than the line of something today?

    That something changes daily. The bot draws a different metric each morning and never runs the same one two days in a row, so a market you found dull yesterday is a different question today. It might be how much the economy grew, how many people posted, how many messages the server sent, how many reactions went out, how much media got shared, how many messages read as happy, how much XP was earned, how many cats were caught, or how much got staked across the casino.

    You back Over or Under, and everyone who backs the winning side splits the entire pool between them, in proportion to what they staked. Your winnings come from the people who called it wrong — which means the payout isn't a fixed multiplier: it depends on how the money ends up split, and it moves every time somebody bets.

    Reading the panel

    The panel shows the implied odds live: if 80% of the pool is on Over, the market is saying Over is 80% likely, and backing the unpopular side pays more precisely because fewer people are sharing it.

    It also carries a chart while betting is open — the last two weeks of whatever is being counted, with today's line marked and the seven-day average band behind it, plus the odds path tracking how the pool has moved through the day. On economy days that chart is candlesticks, because the economy is a running total with a high and a low; on every other day it's a bar per day, because a count has one reading and drawing it as a candle would invent numbers that don't exist. The result card repeats it with today's finally in, so you can see how near it came. The chart keeps itself current whether or not anyone is betting — it refreshes at least once an hour, so today’s running total is never more than an hour old when you look.

    The rules

    • The line is set by the bot, not by staff — it's the middle value of the last seven days of whatever is being counted, so it drifts with the server instead of needing anyone to keep it honest. It always ends in .5, so a day can never land exactly on it and there are no pushes.
    • Nobody can farm the number. On any market that counts what members do, each person only counts up to a limit — 30 messages, 20 reactions, 10 media posts, and so on — and the panel says which limit is in force. Spamming to move the line doesn't work: your thirty-first message counts for nothing. On the two markets about how many people did something, everyone counts exactly once however much they do. Stakes on Pools itself are never counted either, so betting can't move the thing you're betting on.
    • A metric sits out until it's ready. A market only opens on something with seven clear days of history behind it, so a brand-new feature won't be bet on until there's enough of a record to set a fair line.
    • Betting closes in the early evening (18:00 by default) but the day keeps running until midnight. That gap is the point: by closing time you can see how the day has gone, but the evening — where most of the swing comes from — is still unwritten.
    • Settlement isn't a judgement call. When the day rolls over the bot counts up whatever the market was about and compares it to the line. There's nothing to dispute and nobody to appeal to.
    • If everyone picks the same side, nobody wins — there was no one to play against, so every stake is refunded in full.
    • A small takeout comes off the pool (5% by default) and is burned — destroyed, not paid to the house and not added to the jackpot. It's the one way Pools touches the economy at all.

    Winners get pinged on the result card, so you don't have to remember to check back.

    17 No-Contact List

    Blocking someone in Discord stops them messaging you directly — but it does not stop them reaching you through a bot. An anonymous whisper, an AMA question, a reply to your confession: all of those are the bot delivering something on their behalf, and Discord's block never sees them. The no-contact list closes that gap.

    Adding someone stops contact both ways, across every feature that can carry it: whispers and whisper replies, AMA questions and the DM you'd get when one is answered, confession replies, Guess Who, Pen Pals matching, voice rooms, DM requests, and Risky Rolls. If a feature can pass a message between two people, it is covered.

    Some of that is invisible on purpose. In Risky Rolls, for instance, the dice simply never pair the two of you up to ask and answer — there is no error, no missing message, and nothing for either of you to notice.

    They are not told, and they cannot tell

    This is the part that matters most. The other person is never notified that you added them, and nothing they try will reveal it. When they send a whisper it reports as delivered; when they ask an AMA question it behaves like any ordinary hiccup. There is no error naming you, and no way to probe for one by comparing against someone else. You will also not see their entry if they add you — the secrecy runs in both directions.

    You are not notified when they try, either. Attempts are recorded for moderators, who can act if someone keeps trying, without that turning into a stream of notifications about a person you asked not to hear from.

    Beyond the commands below, the dashboard is where review work happens: ticket, jail, and warning review with transcripts, message search, a live server log, and the audit feeds (DMs, whispers, confessions, quotes, Guess rounds, and Anonymous Features — who is really behind each anonymous submission in the party games).

    The Audit Log is the record of what moderators did to members: jails and releases, warnings issued and revoked, ticket activity, and pulls into or removals from a channel. Nothing else is in it. Voice Control in particular is not — a member creating, renaming or abandoning their own voice channel is self-service, and it is by far the busiest thing the bot records, so including it buried everything a moderator actually needed to see.

    Message Search opens with just a regex box and a + Filter button. Filters are added one at a time from that menu — author, channel, mentions, reply-to, emotion, sentiment range, length, attachments, reactions, dates, deleted state, show-bots, sort — and each becomes a small chip showing its value that you can remove with its ✕. Only the filters you are using take up space.

    Click a result to read around it. The hit expands in place into a scrollable box showing the stored messages before and after it in the same channel, with the hit highlighted, and Load older / Load newer at the ends. Opening another result closes the first. This reads the server's own archive rather than Discord, so it still works for messages Discord no longer has — and unlike search it includes bot messages, because leaving them out would misrepresent the conversation.

    Deleted messages stay searchable, badged deleted (or auto-deleted when an auto-delete rule removed them), with the time in the tooltip. The Deleted filter narrows to only those, or only live ones, or one source. Every message that still exists on Discord gets an ↗ link that opens it there; a deleted message doesn't, since the link would land on nothing.

    Message Search's regex box has limits. A pattern that can run forever would freeze the bot itself, so a few shapes come back with an explanation instead of running: a repeat nested inside a repeated group ((a+)+, ([a-z]+)*), a repeated group whose options overlap ((a|ab)*), patterns longer than 300 characters, and repeat counts above 200. Everyday patterns — (cat|dog)+, \d{3}-\d{4}, https?://\S+ — are unaffected. A regex search also stops after 50,000 messages scanned or 5 seconds; if it does, you're told to narrow the channel, author, or date filters and try again.

    /jail user:@user duration:24h reason:Repeated rule 3 violations Mod Places the member in a private jail channel and removes all their roles. The bot DMs them with the reason.

    ℹ️
    Automatic release

    Timed jails expire automatically — you don't need to manually unjail after the duration. The bot checks every 30 seconds and releases with a logged reason.

    🚪
    If they leave while jailed

    Leaving doesn't clear the hold. The record stays, and if they rejoin they're re-jailed automatically — roles stripped again, jail channel restored (recreated if it was deleted meanwhile). You'll get a log entry the moment they leave.

    You usually don't need to do anything. If you'd rather close the hold out, run /unjail with their user ID, or hit Release on the hold in Moderation → Jails on the dashboard, where anyone who has left is marked Left server. Be aware this is a real decision: their old roles are gone for good, since a release means a later rejoin has nothing to restore from. Leaving the hold active is the safer choice if you expect them back.

    20 Tickets, Policies & Warnings

    The escalation toolkit. Tickets create private channels between the member and the mod team (everything logged). Policies let mods propose and vote on rules. Warnings build a paper trail per member.

    ⚠️
    Use tickets, not DMs

    Handling moderation issues in DMs leaves no record. Open a ticket so the full conversation is logged, searchable, and reviewable by the whole team.

    💡
    Pro Tip: Warn / Jail / Ticket — pick the right escalation

    Warn when the rule violation is clear-cut and you want a paper trail without a conversation. Ticket when the situation needs context-gathering, the member has questions, or you'd otherwise be DMing them. Jail when the member needs to stop interacting now — it strips roles, cuts visibility, and saves a transcript automatically. A jail can absorb a ticket conversation; a warning can't.

    Warnings

    /warn user:@user reason:... Mod Issues a warning to a member. The member gets no DM, but the confirmation posts publicly in the channel you run it in — so run it in a mod channel. Stored in the audit log. Admins are pinged when a threshold is reached.
    reason — optional; logged to the audit trail. The member is never shown this text.
    /revokewarn user:@user warning_id:<N> reason:... Mod Revoke a specific warning. Revoked warnings stay in the member's history (they don't disappear) but no longer count toward thresholds. Open Moderation → Warnings on the dashboard first to find the numeric warning ID.
    warning_id — numeric ID from the dashboard's Warnings page.
    reason — optional; recorded in the audit log alongside the revocation.

    Reading a member's warning history lives on the dashboard under Moderation → Warnings — it lists active and revoked warnings with dates, reasons, and the issuing mod. The old /warnings command was removed; the dashboard page is the reference.

    That page can also act on a warning, so you don't have to copy an ID back into Discord. Pick a warning from the list and the buttons sit under its details: Revoke (any mod) asks for an optional reason, then clears the warning the same way /revokewarn does — it stays in the member's history, marked Revoked with your name on it, and stops counting toward the threshold. A warning that's already revoked has no Revoke button, because there's nothing left to revoke. Delete is admin-only and asks you to confirm first: it erases the warning outright, so it vanishes from the member's history entirely. Reach for it only when the warning should never have existed — the wrong member, or a test row. For an ordinary change of mind, revoke; that's what keeps the paper trail. Either way the action is recorded in the audit log with who did it.

    Working a ticket happens on the dashboard under Moderation → Tickets. The buttons under an open ticket are split into two groups, because they do two different things: This ticket (Claim, Close, Dismiss, Transcript) changes the state of the ticket itself, while This member (Warn, Jail, Add Note) writes a permanent record against the person the ticket is about. The highlighted button is whatever the sensible next step is — Claim while nobody has picked the ticket up, Close Ticket once it's yours — and a destructive action is never the highlighted one.

    Ticket Commands

    The persistent Open a Ticket button panel is posted from Moderation → Tickets on the dashboard — pick a channel and press Post Panel. Use it after the panel scrolls off. Each post creates a new panel and older ones keep working, so delete the old message if you don't want two.

    description — optional short summary of the issue; shown in the ticket's opening embed. You can also leave this blank and explain inside the ticket.
    /ticket claim Mod Assigns the ticket to you. You'll receive DM pings for new messages in that ticket until it's closed.
    /ticket escalate reason:... Mod Brings admins into the ticket with a ping. Use when the issue is above your authority level.
    reason — optional; posted in the ticket to explain the escalation to admins.
    /ticket close reason:... Mod Locks the channel and posts Reopen / Delete buttons. The channel remains visible for review until deleted. The ticket creator is DM'd that it's closed.
    reason — optional; included in the closure message and in the DM to the ticket creator.
    /ticket reopen Mod Re-opens a closed ticket (also available via the Reopen button posted on close). Restores write access for the ticket member.
    /ticket delete Mod Permanently deletes the ticket channel. A full transcript is saved to the database first.
    /pull user:@user    /remove user:@user Mod Add or remove a member from the current ticket/jail channel. Useful for bringing in witnesses or additional mods.

    Activity & Engagement Analytics

    ℹ️
    All activity reports live in the web dashboard

    Message volume, Activity Drops, Cohort Retention, DAU/MAU, Newcomer Funnel, Mod Workload, Sentiment, and Quality Score are all interactive panels with filters, sorting, and exports. The Channels panel combines the per-channel health roster (status, score, staleness) with a windowed side-by-side comparison (messages, XP, sentiment, trend). The Discord /activity command has been retired in favor of the dashboard.

    On the Activity panel, the two XP shape views — By Hour of Day and By Day of Week — cover the last 90 days rather than the whole history, and the chart title says so. Older XP is kept as a daily total, which has no hour in it, so "when is this server awake" is answered from the recent months. The same two views in Messages mode still read the full archive.

    The Activity panel also has two comparison views — Today vs Recent Days and This Week vs Recent Weeks. Instead of a bar per week, these lay the current day or week over a shaded band showing the typical range for that point in the day or week, drawn from the last few. The bold amber line is now; the dashed teal line is the median, and the band around it is the middle half of recent history — so a line above the band means you are busier than usual at that hour, not just busier overall. A Compare to picker sets how far back the band looks.     Threads and Channel Metrics

    Anywhere the dashboard lists channels — the Channels panel, the per-channel heatmaps, the homepage's busiest-channels tile — a thread is never a row of its own. Whatever gets said in a thread counts toward the channel the thread was started from, so a channel whose conversation has moved into its threads still reads as busy rather than dead.

    Channels the bot creates and throws away are left out entirely: Pen Pals pairing channels, Voice Master temporary rooms, jail channels, and the bio wizard's setup rooms. They're private, short-lived, and one-to-one, so counting them told you nothing about how the server is doing.

    A handful of old messages can't be placed — ones in threads Discord has since deleted, or in channels that no longer exist. Those are left out rather than shown under an id nobody can open; it's about 3% of a month's messages. Message Search is unaffected and still finds everything, threads included.

    Bots and Metrics

    Every metric on the dashboard counts humans only. Bot messages — yours and third-party ones like Cat Bot, Gamebot, or DISBOARD — are left out of message volume, active-user counts, channel health, participation spread, sentiment, retention cohorts, and the newcomer funnel. A channel kept busy only by a bot therefore reads as quiet, which is the intent: it tells you what your members are actually doing.

    Panels that count messages carry a Show Bots checkbox if you need the other view — handy when you're chasing a bot that's spamming a channel. It's off by default and only affects the panel you're looking at.

    The Message Search panel hides bot messages by default too, with the same checkbox. Searching for a specific bot by author is an exception: if you name the author, you get their messages whether or not the box is ticked. The AI question box follows the same rule, so asking "who posts the most here?" is answered from member activity rather than bot chatter.

    "Bot" means any account Discord marks as a bot, including ones that have since left the server. XP was already human-only, so XP totals and leaderboards are unchanged.

    Command & Panel Usage Admin

    A dashboard panel (Reports → Bot Usage → Command & Panel Usage) showing which slash commands members actually run and which dashboard panels get opened — with counts, how many distinct people used each, error counts, busiest hours, and a daily trend.

    The part worth checking first is Never used, at the top: every registered slash command nobody has ever run, and every dashboard panel nobody has ever opened. That list is judged against all recorded history rather than the date range you've picked — a command last run three months ago is unpopular, not unused — which makes it a straight list of things you could retire.

    ℹ️
    What gets recorded

    For commands: the command name, who ran it, which channel, when, and whether it errored — not the options or text anyone typed into it. For the dashboard: one entry each time a panel is opened, not every background refresh, so the numbers reflect people rather than how long a tab was left open.

    Recording begins when this feature is installed; there's no backfill, so the report is empty until members start using the bot. Commands run in DMs aren't recorded, and neither are commands whose own error handler catches the failure — so the error count is a floor, not a total.

    Command usage is recorded for every member. Dashboard panel usage is recorded for mods and admins only — a regular member browsing their Wellness pages isn't tracked. Entries are kept indefinitely and are only ever cleared by a full data-erasure run — see Data Erasure. The report panel itself is admin-only.

    One-Sided Attention Mod

    A moderator-review report (dashboard sidebar → Reports → People → One-Sided Attention) that surfaces member pairs where one person keeps directing attention at another who isn't returning it. It's built to help you notice fixation or unwanted pursuit early — the shape of "A keeps showing up around B; B never seeks A out" — that's easy to miss message-by-message.

    It looks at three kinds of directed attention over a window you pick (default 30 days): replies & mentions, reactions, and voice-follows (joining a voice channel someone is already sitting in). Three things all have to be true before a pair appears:

    • Enough approaches. Replies, mentions and voice-follows count — the things that ask someone for a response. Reactions do not count toward this: reacting isn't conversation, so an unanswered reaction says far less than an unanswered reply. Reactions still show up in the evidence.
    • It's really this person. The pair has to be a real share of everywhere the initiator's attention goes. Someone who engages ninety people, one of whom answers less than the rest, isn't fixated on anybody.
    • The other person answers them less than they answer everyone else — or doesn't answer at all. This is the part that stops the report blaming people for someone else's habits: a member who rarely replies to anybody would otherwise look like they were freezing out every single person who talks to them.

    Each flagged pair is presented as plain-language evidence chips — how one-sided it is, whether the other person ever responded, how far below their usual they answered this one person, whether contact increased after they went quiet, how much of the initiator's attention is aimed at them, times they followed them into voice, and any rapid bursts. Where a reading has an innocent explanation, the report says so itself (a small friend circle, contact that's cooling off, mostly-reactions that read as ordinary support, or simply too few approaches to tell either way).

    The bar is set low on purpose, so expect a short list with some thin cases on it rather than a permanently empty one. An empty report reads as "nothing concerning here", and that's a promise a report can only keep if it's capable of firing in the first place.

    ⚠️
    A tip, not a verdict

    This report never scores or ranks anyone behind a hidden number, and it never takes any action — it just points your attention at a pattern for you to judge as a human. It also doesn't use or infer gender. Treat a flag as "worth a glance," nothing more.

    Bots are automatically excluded, so a member who replies to or reacts to a bot never shows up here. Reactions and voice-follows are only counted from the day the feature went live onward (there's no backfill), so early reports lean on replies and mentions.

    23 Rules Watch

    A passive AI moderation monitor. Once enabled, Rules Watch screens every public message against your server rules and sorts anything suspicious into a tiered queue: immediate (an alert embed posted to your alert channel with Confirm / False-positive buttons), digest (queued for review in batches), and logged (recorded but not alerted). Labeling events as violations or false positives tunes the signal over time — the stats command shows your false-positive rate. Mods can also right-click any message → Apps → Report Rule Violation to hand-file it as a confirmed example the AI missed.

    ℹ️
    Requires the AI service, off by default

    Rules Watch uses the same local AI model as the AI Moderation Tools and does nothing until you turn it on from the web dashboard. Configure and review queued events on the dashboard's Rules Watch panel.

    ℹ️
    Configure via the web dashboard

    The Rules Watch config panel toggles monitoring on/off and sets which channel receives immediate-tier alerts (each alert includes the flagged message, the matched rule, and Confirm / False-positive buttons that keep working across bot restarts). The retired /rules-watch enable, /rules-watch disable, and /rules-watch set-channel commands are no longer needed.

    The Ledger

    The dashboard panel's Ledger tab is a separate thing from the alert queue, and it works differently on purpose. Where the queue holds the AI's opinion that a message might break a rule, the ledger records only that a specific, narrowly-defined thing was said. It makes no judgment, sends no alert, and has no Confirm / False-positive buttons — there is nothing to agree or disagree with. It exists so that if you are already reviewing someone, the relevant dates are on hand rather than reconstructed from memory.

    Two entries are recorded:

    • DM consent — someone says the consent bot is broken or that they don't know how to use it, and expresses intent to DM a particular person. Asking publicly before DMing is encouraged and never recorded; what lands here is the claim that the bot can't be used.
    • Cross-platform — someone shows they have already looked at another member's content on Reddit, Instagram, OnlyFans, Snapchat, Telegram or TikTok. Asking someone for their handle, or recognizing them from another platform, is ordinary and is not recorded — only demonstrating you went and looked. If the person raised that platform themselves in the last month, nothing is recorded.

    Both are deliberately rare — measured across fifteen months of server history they fire about once a month between them. If the ledger starts filling up, something has been widened and should be looked at.

    ℹ️
    The ledger runs even when the AI doesn't

    Unlike the alert queue, the ledger needs no AI model — it is plain text matching, so it keeps working if the AI service is unavailable. It still requires Rules Watch to be enabled.

    Rules Watch has no slash commands — reviewing and labeling all happen on the dashboard under Moderation → Rules Watch. The event list has tier filters (All / Immediate / Digest / Logged) and shows only unlabeled events by default, so the Digest filter is the batch-review queue. Each row carries ✅ Confirmed violation and ❌ False positive buttons, plus an optional Correct rule box — fill that in when the flag was a real violation but the guard matched it to the wrong rule; it's ignored if you dismiss the event instead. The Stats tab has signal firing rates, label counts, and the false-positive rate. Whether monitoring is on and which channel gets immediate alerts lives on Config → Rules Watch. The old /rules-watch digest, label, stats, and status commands were removed.

    The one Rules Watch action that stays in Discord is the Report Rule Violation message context menu — right-click a message → Apps → Report Rule Violation. It opens a short form (optional rule number and note) and logs the message as a confirmed violation straight away. Mod-only, and it refuses bot messages.

    24 Todo List & Boards

    A shared worklist for the mod team. Tasks can be added from Discord or from the dashboard, and everything lands in the same list. It is moderator-only end to end — members never see it unless you post the board in a channel they can read.

    There is one board you can post, and it answers every question the team asks: is anyone waiting on us?, did we do today's chores? and what else is outstanding? It shows quest sign-offs first, then today's chores as a "did we do it today?" scoreboard, then everything else oldest-first. Until August 2026 the chores and tasks were two separate boards needing two separate channels; servers with one mod channel had to pick, and the tasks half usually lost.

    The Discord board

    The board is a single message the bot keeps at the bottom of a channel. Under Tasks it lists everything pending oldest-first, so whatever has been waiting longest sits at the top. Long tasks are shortened with a “…” to keep the board readable on a phone — the full text is always on the Todo List page, along with the date each one was added.

    • ➕ Add Task — opens a small form for the task and optional notes.
    • ✅ Complete — shows a private picker of everything still open, chores first, then tasks; tick one or several off at once.
    • ✍️ Sign-Offs — reviews the quest claims waiting on staff. See below.

    Add and Complete are moderator-only. Anyone else who clicks gets a private "moderators only" reply and nothing changes. Sign-Offs asks for a little more — see below.

    The board updates itself. Adding or completing a task anywhere — the buttons, /todo, or the dashboard — is reflected within about a minute, and immediately when the action came from Discord. When people chat in the channel, the board deletes itself and re-posts underneath so it never scrolls out of sight.

    Because the board holds your mod chores and the names of members waiting on a sign-off as well as your tasks, put it in a mod channel.

    Quest sign-offs

    Some quests need a person to say yes before they pay. When a member claims one, it lands at the top of the board — one line each, naming the member, the quest and what it pays. They sit above the chores and tasks on purpose: these are the only rows where somebody else is waiting on you.

    This button asks for Bank Manager rather than plain moderator, because approving hands out real currency: you need Discord's Administrator permission or the economy manager role set on the dashboard. Everything here can also be done on the Claims page, and a claim resolved in either place disappears from the other.

    The result is posted in your server's register channel — an approval as the usual payout entry, a denial with the reason you gave, and a claim nobody gets to within a week as an "expired" note. Members are not sent a DM about any of it. A few quests are deliberately kept off that feed for privacy (anything tied to whispers, confessions, AMA questions, Pen Pals or Guess Who rounds); those sign-offs are announced nowhere, and the member simply sees the quest come back onto their board.

    Before 27 August 2026 each claim posted its own card into the bank channel. Those old cards still work if you have any left over; nothing new goes there.

    Today's chores

    The top section of the board, showing only recurring chores. A chore appears here and not in Tasks, so nothing is listed twice.

    Each row shows the chore, whether it's been done, who did it and when, and how many days running it's been done:

    • ✅ — done. The name and time beside it are whoever ticked it off.
    • ⬜ — still to do today.
    • ❌ missed last run — still to do today, and the last one went by without anyone doing it. It clears as soon as the chore is ticked again.
    • 🔥 6 — six days running. Shown from two days up.

    The footer keeps the score for the day — "2 of 3 chores done", alongside the number of sign-offs waiting and the number of tasks still pending. Chores you've paused are left off entirely: a chore parked for the holidays isn't one the team is failing.

    Chores are ticked off with the board's own ✅ Complete button, which offers them above the ordinary tasks. There's no separate Add for a chore — chores are recurring entries with a schedule, set up on the dashboard, and ➕ Add Task adds a one-off.

    When there is nothing at all to offer, the reply says which of three things is true, because they mean very different things: "Every chore is already ticked off", "Nothing due yet" — naming the next chore and when it lands, for a weekly set up on a day it doesn't run — or that no chores are configured at all.

    ⚠️
    Leaving the board unposted takes something away

    The board is the only place in Discord anything can be ticked off. With it unposted, anyone can still add tasks with /todo, but completing one means going to the dashboard. The panel says so on the board's card whenever it isn't posted, and warns you before you remove it.

    ℹ️
    Posted from the web dashboard

    Pick a channel on the Todo List panel and press Post Board. Posting or moving the board is an administrator action; managing the tasks and recurring entries on it only needs moderator. Removing the board deletes the message but keeps every task.

    Who counts as a moderator is the same answer in Discord and on the dashboard: anyone holding a role you've configured as a mod or admin role, plus anyone with Discord's Administrator or Manage Server permission. Set those roles under Server Settings on the dashboard. (Before 18 August 2026 the two surfaces used different rules, so a mod could be let in on one and turned away on the other.)

    Recurring tasks

    Recurring entries put a chore on the list on a schedule — "Post QOTD" every morning at 09:00, "Photo challenge prompt" every Monday. Set them up on the dashboard panel with a daily or weekly cadence and a time of day (server local time).

    These are reminders, not automation. When one comes due the bot adds the task to the list; a moderator then does the thing and ticks it off. The bot does not post the QOTD or the photo prompt for you.

    Each recurring task resets rather than carrying over. When the next one comes due and the last is still untouched, that one is marked missed and a fresh task takes its place. Only ever one copy is outstanding, so nothing piles up — and the days a chore didn't happen stay on the record, which is what the board's ❌ marks and 🔥 streaks are counted from. A missed task can't be ticked off later: it's yesterday's box, and crediting it would put a hole in the streak either side of it.

    Two things deliberately don't reset. Run now adds one instance there and then without touching the schedule or un-pausing a paused entry — and pressing it twice just tells you one is already on the list, rather than marking your first press missed. And if the bot is offline for three days, it comes back and adds one task, marking one instance missed rather than three: the record covers the days the bot was watching, not the days it was away.

    Set a chore up after its time of day has passed and it lands on the list right away, rather than waiting until tomorrow — a 09:00 daily added at lunchtime is something you can tick off this afternoon. It doesn't shift the schedule: the next one still comes at 09:00 tomorrow. A weekly chore added on a day it doesn't run simply waits for its day.

    Each entry can be paused, edited or deleted. Deleting an entry stops it repeating but leaves any copy already on the list, since that is real outstanding work.

Each suggestion says what the feature would give the server, which settings are still empty, and which panel to open.

    It's an ordinary home-page card, so you can move, resize, or remove it like any other.     Something set up but not working?

    Alongside it, admins get a Configuration Problems card — the opposite question. Suggested Setup finds what you haven't configured; this finds what you have configured that silently doesn't work. It checks every channel any feature points at and reports four faults:

    • the channel was deleted
    • it's the wrong kind of channel for what it's wired to
    • the bot can't post in it
    • not one member can see it

    That last one is the reason the card exists. If @everyone is denied View Channel and one role grants it back, deleting that role takes the permission with it — no setting changes, no error, nothing in the audit log naming the channel, and the bot (which usually has its own permissions) keeps posting there quite happily.

    A channel locked down on purpose still has its staff, so it shows a small number of viewers; only a genuinely broken one reaches zero, which is why that's the line the card draws. When several settings share one broken channel they're listed together, because one permission fix clears them all.

    The same card also warns when the database backups have stopped — either the copy taken here every few hours, or the nightly copy pushed to separate hardware. Both are meant to be invisible, which is the problem: when one quietly stops, nothing else changes, and the files already saved sit there looking healthy while the newest one gets older and older. The card is what breaks that silence. It keeps checking even while the bot is disconnected, since a bot that isn't running isn't backing anything up either. Full detail — how old each copy is, how many there are, and the last error if one failed — lives on the System Stats panel under Dev.

    Cleanup

    Message cleanup at two scales, on one panel. A server-wide sweep continuously deletes everything older than a set age across every text channel and thread, apart from the channels you protect.     Configure via the web dashboard

    Inactive Members

    A softer sibling of the jail system for idle members: instead of a per-user cell, everyone held inactive shares one channel. Roles are snapshotted and stripped, the member gets an @Inactive role that can only see that channel, and a persistent panel there lets them open a ticket to be reactivated. Members enter manually or via a sweep; the only way out is /inactive release.

    One-time setup lives on the dashboard under Config → Inactive Sweep → Inactive Channel: pick a channel and press Set Up Channel. That sets the shared inactive channel, creates and wires the @Inactive role, and posts the info panel with its "Open Ticket" button. It's required before mark or a sweep will run. Point it at a different channel any time to move the inactive area — the old channel's @Inactive access is removed for you.

    You never have to make the @Inactive role yourself. If your server already has a role named exactly Inactive, the bot adopts that one rather than making a second; otherwise it creates it. If you delete the role, the bot makes a new one the next time it's needed and says so in your mod channel — worth knowing, because the replacement is empty and anyone who was held inactive is no longer marked.

    /inactive mark user:@member [reason] Mod — Moderate Members Snapshot and strip the member's roles, apply @Inactive, and move them to the inactive channel. Never a bot, never yourself, never an admin — only admins may move a moderator. Members exempted on the dashboard are refused too; lift the exemption there first.
    /inactive release user:@member [reason] Mod — Moderate Members Restore whichever snapshotted roles still exist and remove @Inactive.

    Sweeps also run from Config → Inactive Sweep. Check Now is a dry run — it lists members idle past the threshold without touching anyone. Move Them Now moves exactly those members through the same mark flow, and tells you how many a single run reached if the per-run cap held some back.

    ℹ️
    Configure via the web dashboard

    The Inactive Sweep panel sets the idle-day threshold, the per-run cap, and whether the sweep also runs automatically every 6 hours. The retired /inactive config command is no longer needed.

    Who Would Be Swept Right Now — press Check Now for a dry run against the settings on the page (including a threshold you have typed but not saved). It lists every eligible member, most idle first, with the roles each would lose; click the role count to see them by name. Nothing is moved and no roles change. Because it selects through exactly the same code the real sweep uses, the listing is what a sweep would actually do — with three things called out that the sweep itself never says out loud:

    • the per-run cap, so you can see how many of the listed members one run would actually reach and how many wait for the next;
    • Would Fail — Bot Outranked, members holding a role the sweep would strip that sits at or above the bot's own role. A sweep picks them up and then silently fails to strip them; move the bot's role above theirs to fix it. Roles managed by an integration (booster, Twitch, another bot) don't count here — the sweep never touches them, so they don't block the rest;
    • no tracked messages, shown in place of a last-seen date for members with no message history at all. They are aged from their join date alone, so a long-standing member who was active before the bot started tracking looks identical to one who never spoke.

    Never Sweep These Members — exempt individual members from inactivity holds. An exemption is absolute: both sweeps skip them, and /inactive mark refuses them, so it can't be undone by accident from Discord. Bots, the owner, admins and moderators are already protected and don't need listing. You can exempt someone straight from a preview row with Never Sweep.

    Intake Cards

    Turns your welcome procedure into a live checklist. When someone joins, the bot posts an intake card to greeter chat, pinging the greeter role: a progress bar, the member's account age, who invited them, and the procedure as ✅/⬜ steps.

    The card is a tracker, not a control panel. Welcomers keep greeting, asking the question lists, and running /grant exactly as before, and the card ticks itself as they go. Nothing anyone says is ever recorded — only that steps happened, by whom, and when.

    What ticks each step

    StepTicks when
    GreetedA greeter or mod mentions or replies to the newcomer in your greeter chat channel.
    VerifiedYour unverified role is removed, or a Verified role is granted.
    Role stepsThe member gains the configured role, via /grant or a manual add.
    Question phasesA welcomer presses that step's button on the card.
    Any stepSomeone posts that step's step code (below).

    The first two depend on settings elsewhere, and the panel shows which channel and role it is watching. Greeted watches where newcomers are actually talked to — your greeter chat channel, or the welcome channel when that isn't set, both on Welcome & Leave. It is not the card channel: a greeting posted on the bot's noticeboard isn't the greeting the newcomer sees.

    Verified accepts either shape verification takes: your unverified role being removed, or a Verified role being granted by a bot such as Double Counter. If yours only grants a role, pick it in the Verified role box, or that step can never tick.

    Step codes

    Give a step a step code — any phrase you like — and drop it into the canned message for that stage. A greeter or mod who posts it while @mentioning or replying to the newcomer ticks that one step, from any channel, and the card stays open. So your "we're done with the SFW portion" message ticks the SFW step by itself; a -# subtext line is a tidy place to park the code.

    Codes match anywhere in the message and ignore capitalisation, so no code may contain another one, and none may contain the completion code. The dashboard refuses the save and names the clashing pair.

    Finishing an intake

    Ticking the last step finishes the card. When every box on the checklist is ticked — by a button, by a step code, or by a step that ticks itself — the card closes right there as complete, credited to whoever ticked that last step. There's nothing extra to do: a finished checklist is a finished intake, so nothing done sits in the queue.

    The completion code is how you close a card early. Post the ending welcome message containing the configured code and @mention (or reply to) the newcomer — any channel works — and the card completes with any unticked steps marked skipped: visible in analytics, never blocking.

    Cards only ever close on completion, a mod's Dismiss, or the member leaving or being banned — so the open cards are your intake queue. A card with no progress for the configured window gets one greeter-role nudge reply, never more.

    The nudge only fires when a greeter could actually do something. Someone who joined but never accepted the server's membership screening (Discord's rules gate) has no roles and can't see or post anywhere, so their card sits quietly — and nudges later, if they accept and the intake is still stalled. If someone left while the bot was offline, the stale sweep closes their orphaned card as left rather than pinging you to chase them.

    Earning coins

    When the Economy is running, each step pays a flat award to whoever ticks it — by the card's buttons, by the greeting that ticks Greeted, or by posting that step's code. Paying per step rather than per finished card means two people sharing a welcome are each paid for what they actually did.

    • A step pays once per card — unticking and re-ticking is worth nothing, and a second greeter can't re-claim it.
    • Steps that tick from a role change (Verified, the role grants) have no person behind them and pay nobody.
    • Skipped steps pay nothing.

    The rate lives on Economy → Income Sources ("Ticking a step on a newcomer's intake card"), where the source can also be switched off; an optional intake_step quest in Economy → Quests stacks a bonus on top.

    Procedure reference channel

    • Each block's heading posts as its own message and its content as another, so Copy Text gives you the exact text to paste with no heading to trim.
    • Question lists post one message per question; rewording one edits that message in place, so links keep working.
    • A one-time Import button seeds the editor from the channel's existing content.

Because Discord can only add messages at the bottom, restoring one means re-sending everything below it so the procedure still reads top to bottom; the messages above are left alone, and the status line tells you how many were restored.

    Event Echo

    Posts a small note in main chat whenever something worth your attention is happening elsewhere in the server, with a link that takes you straight to it — so a game running in the games channel doesn't go unnoticed by everyone sitting in the main room. For games, the channel named in the note is itself the link, and it drops you on the game rather than at the bottom of the channel with the game still to find.

    Three kinds of note

    • Something just started — a party game opening for players (including ones the scheduler launches by itself), a Cards Against Humanity game in the tracked Gamebot channel, a Discord server event going live, or a new bounty posted.
    • Last chance — an auction closing within the hour, a prediction-market round whose betting is about to shut, or the weekly raffle an hour before ticket sales close (that one links straight to the shop's buy button).
    • Something just happened — a new week of quests going up (with the pool size and the ⚡ spotlight reveal), or a community goal crossing one of its 40% / 70% / 100% tiers. Nothing to join here, so these link to the economy panel instead of inviting you in; they only appear if that panel has been posted.

    It never pings

    Echoes are silent by design: no role is tagged and nobody is notified — the note is there for people already reading the channel. Results are never echoed, only things you can still act on or worth marking, so the link is always worth clicking.

    Rate limits keep it rare: the same kind of game at most once an hour, and nothing at all within ten minutes of the previous echo; anything arriving inside those windows is skipped rather than announced late. Last-chance notes and the two "just happened" notes are the exception — they happen on a fixed, rare schedule and there's no later moment to retry them, so they always get through, but still only once each. There are no slash commands.

    The weekly "quests are up" announcement used to be a separate post in the leaderboard channel that pinged the economy game role. It now arrives here instead, which means it no longer notifies you — and community goal tiers used to be written up by the community host rather than posted by the bot.

    Announcements

    Queue server announcements on the dashboard, preview them, and set a post time — the bot posts them for you. Each announcement is a rich embed (title, markdown body, optional image, accent color that defaults to your server branding) plus an optional plain-text line shown above the embed. Mentions only ping from that plain-text line, and only when you explicitly pick them: no mentions, one role, or @everyone — nothing pings by accident. Times are server-local (the timezone offset from the Global config panel).

    ℹ️
    Manage via the web dashboard

    The Announcements panel (admin-only) has the queue, a live Discord-style preview while you type, and a Sent history. Save without a time to keep a draft; add a date and time to schedule it. Post Now sends within a minute. Sent items keep an "Open in Discord" jump link and can be cloned back into a fresh draft. If the bot was offline at post time it still posts up to 2 hours late; past that the item is marked as missed instead of posting stale news — clone and reschedule it.

    Role Buttons

    An announcement can carry up to five role buttons. A member clicks one to give themselves that role and clicks again to drop it — the reply is only ever visible to them. Handy for opt-in pings, event signups, and notification roles: post the announcement once and the button keeps working from then on, including after the bot restarts and even if you later delete the announcement from the queue.

    Give each button a role, and optionally a label (blank uses the role's own name, so renaming the role renames the button), an emoji, and a color. Leave the button list empty for a plain announcement.

    ⚠️
    Roles with mod powers can't go on a button

    Any role carrying Administrator, Manage Server / Roles / Channels / Messages / Webhooks, Kick, Ban, Timeout, or Mention Everyone is refused, as is any role above Dungeon Keeper in the role list. Unlike Role Menus there's no override — an announcement is public and stays clickable forever, so this one is a hard no. The check runs again on every click, so if a role picks up mod permissions later, the old button stops handing it out on its own. Members who already have the role can always still remove it.

    28 Network Analytics

    Interactive graph and matrix views of who interacts with whom. Useful for spotting cliques, isolated members, and invite trees.

    Two panels read the same data in different ways, both under Reports → Social Graph:

    • Interactions — the list view. Top pairs and most-connected members as sortable tables, with a bar chart and a focus-member filter. Best when you want a name and a number.
    • Connection Graph — the picture. A drag-and-zoom network map where each dot is a member, dot size is how much they interact, line thickness is how strongly a pair does, and colour is the friend group the maths found. Above it sit the health numbers for the network as a whole — how tight the friend groups are, how many of all possible connections exist, how often interaction goes both ways, and how many hops separate any two people. Below it: who bridges otherwise separate groups, how big each group is, which members have no recorded interactions at all, and a grid of how much each group talks to every other group. Controls let you change the period, focus on one member, hide groups, thin out weak connections, switch layouts, and go fullscreen.
    ℹ️
    Network analytics moved to the web dashboard

    The Interactions graph and Invite Effectiveness reports — plus the interaction-history and member-events backfill scans — are now interactive panels on the dashboard with filters, timescale switching, and node-level drill-downs. The standalone /connection_web, /interaction_heatmap, /invite_web, /interaction_scan, and /member_events_scan slash commands have been retired.

    30 QA Tracker

    A volunteer testing crew for the bot itself. Each new feature lands as a QA card in the testing channel — an embed carrying a short checklist of things to try, with Pass / Fail / Blocked buttons. One card per feature, posted when that feature ships, written as steps you can follow without knowing anything about the code.

    • Members holding the configured QA-crew role click a verdict. Fail requires a "what went wrong" note, which lands in the card's thread.
    • The first Pass turns the card green as verified.
    • Your first verdict on a test pays economy currency instantly, up to a daily cap — re-clicking updates your verdict without re-paying.
    • Until an admin configures the QA-crew role, the buttons are admins-only.

    A card that's stayed verified (green) for 10 minutes is automatically deleted from the channel to keep the queue tidy — the verdicts and payouts stay on record, just the message goes.

    ℹ️
    Admin oversight on the web dashboard

    The Dev-section QA Tracker panel (admin-only) has the status board with every test and its verdicts, a top-testers scoreboard, and the config knobs: QA-crew role, channel, reward amount, daily cap, and enable toggle. A bogus verdict can be voided there — the paid coins are clawed back and the card's status recomputes. Archiving retires a card.
