# Games System — Feature Spec

A 17-mode party-games suite. Every mode is one subcommand under a single top-level `/games` command group: players start a game with `/games play <slug>` (e.g. `/games play ffa`), which spins up a public embed with buttons; players join and play in-place. Games share a per-channel session window for the `/recap` highlight reel, a per-channel allowlist and per-guild enable/disable matrix (both managed from the web dashboard), an optional audit channel for anonymous content, a question bank with AI-generation fallback for prompts, and a dashboard for content authoring. Bank draws are round-robin (least-recently-served row first, so a small pool doesn't repeat until every row has been served once — see **Question-bank / AI-augmented games**). Games also feed the economy — completing quest-relevant actions credits economy quest triggers (see **Economy integration**).

The companion 1-v-1 nickname duel **Pressure Cooker** and the dice game **Risky Rolls** appear in the shared game registry (`GAME_ICONS`/`GAME_NAMES`) but are **separate features** with their own entry points and specs — they are not part of this suite. See [[pressure-cooker-spec]].

> **Command surface.** Only the `games` group is registered to the command tree (`command_groups.py`). Party games hang off the nested `games play` subgroup; meta/admin commands hang directly off `games` or its `config`/`dev` subgroups (the `track` subgroup that used to sit alongside them was removed 2026-07-28 — see External Tracking below). `/recap` and `/support` are top-level commands. There is no bare `/ffa`, `/wyr`, … — those forms are historical and no longer exist.

External tracking is a format-agnostic collector (the `/games track *` commands that configured it were replaced by the dashboard panel on 2026-07-28): an `on_message`/`on_message_edit` listener banks every message from a watched channel+bot RAW (keyed on message id, de-duplicated across restarts/edits) into `games_external_messages`. Nothing is parsed at ingest — metrics are derived later, so a format change never loses history. Each watch carries a `kind` selecting a parser (`games_external/parser.py`); migration 097 generalised the one-bot-per-guild table to multiple `(channel, bot, kind)` rows, and **migration 135 widened its key to `UNIQUE(guild_id, bot_user_id, channel_id)`** so one bot can be watched in many channels. Before that a bot was capped at a single channel and every game it ran elsewhere was silently dropped; the collector cache is keyed on the `(bot, channel)` pair to match.

**Concurrency.** Games running at the same time in different channels each pay out independently, and need no coordination to do so: every payout is a pure function of its own channel's banked history (`recent_channel_messages` filters by channel), so N channels is just N independent backward scans. Nothing is tracked while a game is in flight — there is no game registry, and no state survives between messages.

**`gamebot` is live** (renamed 2026-07-25 from `gamebot_cah`), covering three sub-games that share one Discord bot account: Cards Against Humanity, Connect 4 and Anagrams. Every terminal message (`is_terminal`) goes through the single `_pay_gamebot_game` entry point, which reconstructs the game's window (`current_game_window`) and identifies the sub-game (`identify_game`) before dispatching:

- **Window bounding is anchored on the game's own lobby embed** (`<host> is starting a <Game> game!`), walking back from the terminal and stopping at that lobby, or at the previous game's terminal if the lobby has aged out of the banked slice. Anchoring on the lobby means a window holds exactly one game's messages.
- **The sub-game is read off that lobby, never off the terminal message.** CAH and Anagrams end with the *identical* `<@id> is the winner!` wording, so a terminal can't tell them apart — dispatching on it credited every Anagrams game as a one-player CAH game at score 0 (found and fixed 2026-07-26, with 3 such games in the banked history). A lobby naming a game we have no parser for (Chess, Poker, …) yields `None` and pays nobody, rather than falling through to a wrong guess.
- **Abandoned lobbies pay nobody.** `Not enough players joined the game!` still gets a *Game over!* from Gamebot; `is_abandoned` catches it. These used to be paid as Connect 4 games, because the roster reader picked up the **Joined Players** field off *any* embed — including an abandoned CAH lobby's. The join-phase reader is now gated on its embed titles and shared across sub-games (`players_from_join_phase`), the join phase being identical for all of them.

**Gamebot's 2026-08-15 format change.** Overnight Gamebot rewrote every CAH string, and because none of the new ones matched, DK stopped paying CAH entirely — the last `gamebot_cah` payout is 2026-08-14, while `catbot` and `coordle` kept paying daily. The parser now speaks both vocabularies, since a pre-update game can still be in flight:

| | through 2026-08-14 | from 2026-08-15 |
|---|---|---|
| standings | *Current Standings* embed, `<@id>: 3` in the description | a **Standings field** on *Round winner* / *Final scores*, `<@id>: **3**` |
| submissions | *Submission status*, `✅ <@id> Submitted!` | a **Submissions field** on *Play your card*, `✅ <@id>` / `⬜ <@id>` |
| finish | *Game over!* + `<@id> is the winner!` | *Final scores* — **no winner is declared at all** |
| lobby roster | **Joined Players** field | **Players (6/12)** field |

Two consequences beyond the string swap. **The winner is derived**, as the top of the last standings, since Gamebot no longer names one; CAH is first-to-N so a completed game has a unique leader, but a game Gamebot drops part-way can leave the lead tied and then *every* tied player wins (`extract_cah_game` returns a **list**, which `pay_cah_game_by_score` already accepts — Wordle ties the same way). An all-zero standings yields no winner at all rather than an N-way tie. **`Something went wrong` is terminal**, so a game Gamebot drops still pays out the rounds that were played (Billy's call, 2026-08-16). One posted 1.4s *after* a clean *Final scores* is not a double payment: each terminal claims on its own message id, so what protects the ledger is the window — bounding back from the crash stops at the *Final scores* before it, leaving a one-message window with no standings, which pays nobody. Replaying the whole banked history through the fixed parser reproduces all 43 existing payout rows unchanged.

Connect 4 and Anagrams **have not been verified against the new format**: the last banked Connect 4 lobby is 2026-08-08 (pre-change) and no Anagrams game has ever appeared in the archive at all, which is why `gamebot_anagrams` has no rows. The shared join-phase reader handles both roster field names, but Connect 4's new terminal wording is unknown until someone plays one.

Per sub-game: **CAH** reconstructs final scores (last standings post, folding in submission-only/winner-only players at 0) and calls `pay_cah_game_by_score` — the top scorer earns `EconSettings.reward_cah_win_max` (default 50, dashboard-configurable), everyone else a ratio of it, firing the same `party_game`/`game_win` triggers. Standings are accumulated and never pruned, so a player who leaves mid-game keeps the score they earned and is paid for the rounds they played, even though Gamebot cuts them from every later standings. **Anagrams** reads its *Scoreboard* embed, whose **field names** carry `"<username> - N POINTS"`; players are named by username rather than mention, so they're resolved with `resolve_named_scores` (the same `get_member_named` lookup Cat Bot uses) and then paid through `pay_cah_game_by_score` with `game_key="anagrams"`, sharing the same cap. **Connect 4** reconstructs roster + winner (`<@id> has won!`) and calls the flat `pay_game_rewards` — win/lose only, no score to scale by. All are paid once via a `games_external_payouts` ledger (migration 099) keyed on the game-over message id, independent of `parse_status` (which edit-recapture resets).

**`catbot` is also live**: Cat Bot catches are parsed from message content (`{username} cought <:raritycat:…>`, reverse cats un-reversed, "blessed…doubled" ×2), the catcher resolved by username→member (`get_member_named`), and `pay_cat_catch` credits rarity-tiered coins (common 1 → divine 300) plus the `cat_catch` quest trigger — paid once via the same ledger, keyed on the catch message id.

**`wordle` is live.** The Wordle bot posts one self-contained daily digest per group — no embeds, no lobby, so unlike every Gamebot game this needs *no backward scan at all* and is keyed on the digest's own message id:

```
**Your group is on a 9 day streak!** 🔥 Here are yesterday's results:
👑 3/6: <@490886726076727296> <@83699131368865792>
4/6: <@203866639005908992>
X/6: <@1069501326184153088>
```

Scoring is **inverted** relative to CAH/Anagrams — fewer guesses is better — so `parse_wordle_results` flips it (`1/6` → 6 … `6/6` → 1, `X/6` → 0, which keeps a failed player in the roster for `party_game` while earning no coins) and the shared `pay_cah_game_by_score` does the rest. Ties on the 👑 line are normal, so that function now accepts **several winners**. Wordle mentions only some players and prints the rest as a bare `@Name`; those are split on the `@` (not on whitespace — real display names contain spaces, e.g. `@communal potato`) and resolved with `resolve_named_scores`. In the observed history that recovers 21 of 22 such entries.

**`coordle` is live.** Co-ordle is a *co-operative* hourly word puzzle whose board embed (`Co-ordle for <t:…:f>`) lists each guess with its player and points. Two properties make it unlike everything else:

- **A new board message is posted per guess**, each showing the whole round. So the payout is keyed on the **round's own scheduled timestamp** (`coordle_game_key`), not a message id — keyed on the message it would pay the same round once per guess. Those values (~1.7e9) cannot collide with Discord snowflakes (~1.5e18) in the shared ledger.
- **There is no terminal message.** `This Co-ordle has ended` is only a rejection sent to a late guesser. Finality is read off the board: six greens in a row means solved, no unplayed rows left means exhausted. A round that simply times out with rows to spare stays open and never pays — 16 of 1,887 observed rounds, the accepted cost of having no end-of-round signal.

Points are the inline `**+N**`, or `**+N (+M)**` where a bonus applies, in which case the player earned **N+M**. That reading was verified against the bot's own cumulative leaderboard across consecutive snapshots: `N+M` reproduced the leaderboard delta for 79% of player-rounds versus 0.5% for `N` alone (the remainder being rounds clipped by a snapshot boundary or its top-10 cut). The leaderboard embed itself is cumulative all-time and is deliberately **not** used for payout — doing so would re-pay every prior round.

**Host bounty.** Gamebot names whoever started a game in its lobby title (`efficientpanic is starting a …`) — by username, so `host_from_lobby` reads it and the cog resolves it with `get_member_named`. Until 2026-07-26 no external game passed a host at all, so every tracked Gamebot game paid its players and nothing to its host, while native party games had always paid one. The bounty itself is unchanged and now lives in the shared `pay_host_bounty`, called by both the flat faucet and the score-proportional one: `joiners` counts players *other than* the host, so a game nobody else joined pays nothing (the anti-farm gate, which is also what makes an abandoned lobby pay its would-be host nothing). `scripts/backfill_gamebot_hosting.py` replays the backlog — dry run by default, idempotent via a `meta.game` stamp on each `game_host` ledger row (the payouts ledger can't be reused: it's keyed on the Game-over message id, and a game whose *participation* is already paid still owes its host). Booster status must be passed in with `--boosters`, since it lives only on the gateway (`member.premium_since`) and is recorded nowhere in the database.

**Replaying unpaid history.** `scripts/replay_gamebot_games.py` (dry run by default, `--apply` to write) replays every finished game with no ledger claim, feeding each through the *same* parser functions the cog calls — so backfill and live payout can't diverge. It claims before crediting, so a game already paid live is skipped structurally rather than by a cutoff, and fires quest triggers on each game's **own local day** so a backlog doesn't land on today's board at once. Same shape as `scripts/backfill_cat_catches.py`. **Wordle and Co-ordle have no equivalent replay**: their history predates tracking and sits in the general `messages` table rather than `games_external_messages`, and paying 1,581 historic Co-ordle rounds at once would be a large unplanned coin injection. Both start paying from the moment their watch is configured.

### Dashboard-managed configuration

These settings are **live and enforced** but are configured from the web dashboard (`/api/games/*`), **not** slash commands. There are no slash commands to manage them.

- **Channel allowlist** (`games_allowed_channels`, `guild_id`-scoped as of migration 122). Every *question-bank* game preflights `check_allowed_channel`; the six duel/group games in `dk_pvp_games_suite_spec.md` do **not** — their only channel rule is their own per-game `channel_allowlist`, and their panels say so. A channel that isn't on the allowlist refuses every question-bank game. The dashboard channels panel and the game-history/stats views are filtered to the active guild, so a host of one guild can't see or delete another guild's rows. (Legacy rows predating migration 122 carry `guild_id = 0`, treated as a wildcard by the in-Discord gate but invisible in the guild-scoped dashboard until reconciled.)
- **Per-guild per-game enable/disable** (`games_game_config`, default enabled —
  no row means on). Checked by `check_game_enabled` at the start of every
  game's command **and** by the scheduler before each auto-launch. Set on
  **Games Global Config → Available on This Server**, which lists every type in
  `routes/games.py:ALL_GAME_TYPES`; games with their own settings page repeat
  the same switch there, and Photo Challenge's lives on its own page instead
  (it is deliberately absent from the list, so the standalone panel stays the
  only writer of its row). The key is the game type string the bot reads, so
  each entry must be spelled exactly as its reader spells it or the switch is
  unreachable. Before 2026-08-29 seven games could not be switched off at all:
  `mfk`, `compliment`, `ttl`, `hottakes`, `story` and `fantasies` had no panel
  and never called the check, and `legitlibs` was missing from the list so its
  PUT 404'd; the list also carried a phantom `risky_roller` while the scheduler
  asked about `risky_roll`. The six duel/group games use the same store, keyed
  by each cog's `GAME_KEY`, checked at both creation entrypoints. **A panel
  labels the switch for everything that reads it.** `legitlibs` was labelled
  "Include in Scheduled Games" until 2026-08-29 and kept that label for one
  commit after its start command began gating on the switch, which made an
  admin unticking it to trim the schedule silently kill `/games play legitlibs`.
  `risky_roll` was the mirror-image bug: it sat in the Global Config list under
  "Available on This Server" while `/risky start` never consulted the switch, so
  the list promised a refusal that never came. Both now gate their start command
  and both panels say "Available on This Server", the same words the Global
  Config list uses for the same row.
- **Player limits are offered only where there is a lobby.** Most Likely To and
  Mt. Rushmore Draft create their game with `state="joining"`, so a floor and a
  ceiling have somewhere to apply; every other game goes straight to
  `state="playing"` and its panel offers neither. Both ceilings are clamped to
  **25** whatever the dashboard stored, because the per-round vote is a Discord
  `Select` and a larger lobby would 400 the message — the same reason
  `mfk` caps its pool. Rushmore had no join cap at all until 2026-08-27: the
  Join button appended unconditionally while the vote roster was sliced at 25,
  so the 26th player drafted a full board and then could not be voted for.
  **LegitLibs is the exception that proves the rule**: its ceiling isn't a dial
  but arithmetic on the chosen template's blank count (`ceil(n/10)` to
  `floor(n/5)`, each player filling 5–10 blanks), so the template editor shows
  the range instead of collecting it, and both modes turn away a joiner once
  the lobby reaches it (`validation.lobby_is_full`). Until 2026-08-29 the two
  numbers were editable fields whose values were discarded on save — create
  always derived them and update overwrote them whenever blanks rode along —
  and nothing enforced the ceiling anyway.
- **17 dials that no cog read were removed on 2026-08-27**, across WYR, AMA,
  NHIE, Price, Rushmore and Clapback. Three were worse than inert: WYR's "Hide
  Who Voted for What" could not have done what it said (naming is driven by a
  separate `revealed` flag set by a host/mod button, and `anonymous` only gated
  whether per-vote audit rows were written, so wiring it would have suppressed
  a mod trail while hiding nothing from members); AMA's key was `screened`
  while its cog reads `mode`; and Clapback's "Include NSFW Prompts" contradicted
  the house rule that NSFW gates on `channel.is_nsfw()` and never on a bot-side
  toggle.
- **Audit channel** (`games_audit_channel`). When set, anonymous submissions are mirrored there with the original author visible. **Only** anonymous submissions: nothing writes a game-lifecycle event there, and the panel hint no longer claims otherwise. This is now a *mirror*, not the record — every anonymous action is also written to `anon_audit_log` and surfaced on the admin dashboard regardless of whether this channel is configured (see `anon_audit_spec.md`).
- **Game Host / editor role** (`games_editor_role`). Holders pass the Game-Host check for content authoring on the dashboard and can add/remove other players via `/games join|leave`.
- **LegitLibs per-channel tier cap** (`legitlibs_channel_config.max_tier`, default 4), set per-row on the Games Config → Allowed Channels table, and LegitLibs template authoring. The LegitLibs **blank vocabulary** is not in that list and is not configurable — see *Environment / files* below.

### Dashboard

**Play Statistics** (`/api/games/stats`, route id `games-logs`) reports games played, rounds, unique players and a per-type breakdown, all-time or for the **last 30 days** (`?days=`; the bank count is a library size and is never windowed). The game name / icon map rides with the response (`games`) and the breakdown iterates every type the history holds, most played first — the panel carried its own eight-entry copy until 2026-09-04 and drew Truth or Dare, the second-most-played game, nowhere (platform-26). **Unique Players** is rebuilt server-side from each archived payload with the payout's own per-game extractors (`game_roster.roster_from_payload`), so it counts members who took part — voted, joined, answered — and not hosts plus whichever payloads happened to carry a `players` list; a photo card carries its poster count in `player_count` but no member ids (`photo` is in `NO_ROSTER_TYPES`), so photo posters are **not** in Unique Players (see `photo_challenge_spec.md`). Meadow Mahjong's settled hands are self-recorded rows (`game_type = 'mahjong'`, human seats under `players`; `mahjong_service`), named **Meadow Mahjong** in `GAME_NAMES` and read by the same extractor, so they count too — the table is not on the games menu, so it has no `GAME_ICONS` entry. The history filter offers every type ever played (`history_types`), so a game that played last year is still selectable inside the 30-day window.

The dashboard mirrors the config surfaces above and adds full LegitLibs template authoring, question-bank import/export, and AI-prompt editing. Banks also share a **global pool** — bank rows stored under the reserved `global` game type, which gameplay never selects. Every bank manager has a per-question *Pool* button (copy to the pool; duplicate texts are skipped, and Traditional's category tags are translated to the generic `nsfw` tag or dropped) and a pool browser that imports selected pool questions into that game's bank (duplicates skipped; Traditional requires choosing the category the imports are filed under, other games carry the pool tags over). Two permission tiers gate it: `mod` (Administrator / Manage Server) for config writes, and a Game Host tier (Administrator OR the configured editor role) for content authoring (bank, templates, AI generate, history, stats). AI-prompt config is re-loaded per request so dashboard edits take effect mid-game without a restart. FFA's `truth`/`dare` tags are reserved the way `nsfw` is — a truth round draws only rows tagged `truth` — so its bank panel states that contract in its hint rather than enforcing a category the way Traditional does; an untagged FFA row is valid and simply only ever comes up in a random round.

## Behavior

Every interactive game follows the same skeleton: preflight (channel allowlisted? game enabled for this guild?), insert a "live game" row keyed by channel id (`games_active_games`, which carries its `guild_id` since migration 204 — stamped by `create_game` from the launcher's guild, or from the channel allowlist when a launcher passes none), post the embed + view, and on close archive the game's final payload into a history table and free the live-game slot. Each channel can host at most one live game at a time. A 24-hour sweep closes orphaned games that nobody closed; closing copies the payload into the history archive and frees the slot. (Photo Challenge is fire-and-forget — it records a history row for stats but keeps no interactive state, since people just reply in the channel.)

The preflight guards **every door into a launch, not just the slash command**. The dashboard scheduler re-checks the enabled dial itself; a **feature-rotation** launch (`feature_rotation_service.start_room_game` → `_launch`) reads `check_game_enabled` against the base game type (`SCHEDULE_BASE_GAME_TYPE`, so a display variant honours its base game's toggle) and logs-and-skips a disabled game; and the recap cards' **Play Again** (Clapback) and **Run Again** (Name Your Price, Mt. Rushmore Draft) buttons go through `game_manager.relaunch_refusal`, which since 2026-09-04 is a thin name for **`games/utils/launch_guard.launch_refusal`** — the one guard every door is meant to share and the single owner of the refusal copy. It runs, in order: allowed channel; the enabled dial (the game named from `GAME_NAMES`, or an explicit `label`); a **busy check** — a game already running in the channel is refused by name with a jump link to its board when the anchor message is known ("❌ There's already a game running in this channel — **Would You Rather** (jump to it). Wait for it to finish, or the host or a mod can `/games end` it first."); and, for the **bank-only** games (`BANK_ONLY_TYPES`: Clapback, Would You Rather, Never Have I Ever, Most Likely To — Rushmore and Name Your Price default to host-supplied material and are deliberately not listed) launched without host-supplied material, an **empty-bank check** through `has_matching_questions` honouring the host's tags and the channel's age-gate, refused with the dashboard hint Clapback already used ("No prompts in the bank for Most Likely To. Add some from the Games question bank on the web dashboard."). It returns the message or `None` and never sends — the caller does. **Every party-game slash entry runs the guard** (since 2026-09-04): Would You Rather, Never Have I Ever and Most Likely To pass the host's tags, the channel's age-gate and `host_supplied` when a `question:` was typed; Clapback passes the age-gate (its old private `has_clapback_prompts` pre-check is now the guard's bank check); the other twelve — Truth or Dare, Two Truths, AMA, Compliment, MFK, Story Builder, Name Your Price, Mt. Rushmore, ffa/ffa_banner, LegitLibs — pass nothing extra. So a double-tap in a busy channel and a bare `/games play mlt` on an empty bank are refused at the command with the shared copy (platform-18: sixteen entries launched a second board on top of a live one, Truth or Dare double-started four times in prod — trivia-tail-88; platform-27: a bare `/games play mlt` filled a lobby and died at Start on an empty bank). LegitLibs' private guard, which only refused another *LegitLibs* round, is gone with the rest; ffa keeps its own tag-filter check after the guard (it is not bank-only) but sends the guard's `no_tag_match_message`. No slash entry carries a refusal literal of its own any more. Wiring the scheduler and rotation through the guard is what remains of common-lib A.1. Until 2026-09-02 those two doors had no guard, and a host could keep a game an admin had just switched off alive from the recap card indefinitely (`docs/reviews/2026-09-02-games-deep-review-findings.md`, safety-sweep-3/4, platform-28).

The games cluster by shape; each cluster shares interaction patterns.

### Question-bank / AI-augmented games

**Would You Rather, Never Have I Ever, Most Likely To, Mt. Rushmore Draft, Name Your Price, Clapback** draw prompts from the pre-seeded bank and nothing else — the AI fallback was removed 2026-07-28 with the "Prompts & AI" studios. When the bank has nothing to serve mid-game, **WYR, NHIE and MLT open the round *waiting for a prompt***: the board shows "⏳ No question yet — press ✍️ Pose … to submit one and the round starts" with only Pose, 🏁 End Game and Help live, and the first posed prompt opens that same round in place (`begin_round`); the game never ends itself on an empty bank (vote-games-50 — until 2026-09-04 all three ended the game while telling the host to use a Pose button `end_game` had just removed, and NHIE paid nobody). A **Would You Rather bank row is `option A | option B`**; a row typed as prose ("Would you rather X, or Y?") is split on its last ", or " / " or " after the "Would you rather" lead-in and trailing "?" are dropped (`question_source.split_wyr_options`, shared with the dashboard, which stores what it can split in the `a | b` shape and refuses what it cannot with the shape spelled out — vote-games-49: all 23 prod rows were prose and a bank-fed game marked one served and ended in the same second). **AMA has no bank** — every AMA question is typed by a member during the game, no draw function has ever read `game_type='ama'`, and the bank UI its panel used to offer (retired 2026-08-29) curated questions that could never be asked. The bank API still accepts the type so an old full-bank export re-imports. Bank draws are round-robin, not pure-random: each row tracks when it was last served and selection prefers the least-recently-served match (ties broken at random), so a small pool doesn't repeat a question until every row has been served once — including across separate game sessions. **Tags are stored lowercase and matched case-insensitively** — one rule, `question_source.normalise_tags` (strip, lowercase, drop empties, dedupe), is applied by the dashboard on save, read and filter and by `question_source._parse_tags` on draw, so the reserved tags (`nsfw`, FFA's `truth`/`dare`) and any requested filter match a row however it was typed or imported. That includes the NSFW gate: a row tagged `Nsfw` is adult and is served only in a channel Discord itself age-restricts (`channel.is_nsfw()`); until 2026-09-02 the gate compared the literal string and 68 prod rows imported as `"Nsfw"` were serving in SFW channels (safety-sweep-1). Most Likely To's vote select also consults the no-contact list — a blocked voter→target pick is dropped behind the ordinary "✅ Voted" ack (`docs/no_contact_spec.md`). The multi-round ones rotate through rounds: each round opens with a fresh question (from the bank or a host-supplied queue), collects votes or submissions, closes the previous round's view, then opens the next. `wyr` parses an optional `a | b` opening question; `nhie` clamps `lives` to 0–10 and disables elimination when set to 0, and declares "last one standing" only once **at least two players have ever registered and someone has been knocked out** (`find_winner`; `lives` never drops a row, so its size is the max roster — vote-games-51: a round in which exactly one member voted used to crown and pay that member); `rushmore`, `price`, and `clapback` show a live countdown timestamp the host can skip with a button. **`price`** (trivia-tail-85/86/87/94/97, 2026-09-04) opens a **join lobby** (`LOBBY_GAME_TYPES`, floor `games_price.logic.MIN_PLAYERS` = 2, `start_in` with a countdown auto-start through `PriceCog.auto_start`; a `joining` row is recovered as its lobby view): the roster is what lets a round close early — the submission view takes `expected_ids` (the ids in `payload['players']`) and skips its timer once **every joined player** has answered (`roster_all_in`). Submission stays open to the whole channel, so the rule is on ids, never a headcount: a spectator's price counts in the reveal and the vote but fills nobody's seat (until 2026-09-05 three prices closed a three-seat round with a joined player still locked out), and the board's counter reads `Submitted: **3** (2/3 who joined …)`. The embed names the host's **⏭️ Skip**. With no `source:` chosen the game runs on the bank when it holds a matching scenario and on the host otherwise (`resolve_source`); `ai` and `both` are gone from the slash choices and the schedule schema (a persisted value runs on the bank). A host- or player-written scenario is prompted by a **📝 Write Scenario** / **🎲 Draw From the Bank** row on the board itself (host/mod gated; `players` opens Write to anyone; two minutes, then the bank) — never a public `<@host>` ping. Write is refused ("Someone already submitted a scenario!") only once the modal has actually resolved — a submit, or the bank drawn — never on *open*: Discord does not report a dismissed modal, so a host who closed it can press Write again (until 2026-09-05 the first press took the slot and the host sat locked out for the whole wait, and with `host` source on an empty bank the round then skipped). The vote needs **three submitters** (`MIN_VOTERS`): two would be a forced 1-1 cross-vote and a guaranteed double tie, so a two-price round is revealed and moves on. **End Game** on the submission view (host/mod, behind the confirm) records the round's prices so far and runs the recap path, which pays everyone who submitted in any round; the recap's **🔁 Run Again** is open to any member and opens a new lobby with the presser as host through `launch_refusal` — that *is* the hand-off, so the separate **Hand Off** button (trivia-tail-97) is gone, matching Rushmore's card (social-prompt-45). `rushmore` drafts in one of two modes (slash `mode:` arg or dashboard **Draft Mode** dial; **default blitz** since 2026-09-04, social-prompt-37 — a six-player snake is 24 timed turns of dead time for five people): **blitz** has everyone with an empty slot pick simultaneously each round, duplicates resolved first-come with an ephemeral "taken, try again"; the board redraws as each pick lands (todo #208/#209 — before this the board only updated at the start of the next round, so a blitz pick vanished into an ephemeral "✅ Picked!" and nobody else saw it land until the round turned over) — a burst of near-simultaneous picks coalesces into one edit rather than one per pick (`RedrawCoalescer`), and the round's countdown is fixed when the round opens so a mid-round redraw doesn't reset it, while **snake** pings each player on their turn — one message per turn carrying its own **Make Your Pick** button so nobody scrolls back to the board, and the 10-second nudge *edits that same ping* rather than posting a second one. After the draft, skipped slots get a 60-second **backfill window** (own button, duplicates still blocked) before boards go final; boards that are still all-skip are hidden from the FINAL BOARDS embed and excluded from the vote. The vote card says **anyone in the channel can vote** (always true; never stated before), and a tie is broken on fewest skips, then lowest total pick time (`tally_votes(skipped=, pick_times=)`; only a dead heat after both is shared — social-prompt-36, every tied uid used to win and be paid). The player floor is **3** in `clamp_player_limits` and on the dashboard: a two-player draft always ties 1–1 since nobody can vote for themselves. The recap's **🔁 Run Again** is open to any member and relaunches with the presser as host through the launch guard — that *is* the hand-off, so the old host-gated **Hand Off** button (a command hint that disabled Run Again) is gone (social-prompt-45). `clapback` pairs answers into head-to-head matchups with a special-case round-robin for 3-player games; a unanimous winner earns a "CLAPBACK!" bonus, and an odd submitter count gives one player a bye worth that round's average score; since 2026-09-04 a matchup closes once every eligible player has voted (decision D1, reversing the June rule that every vote ran its full timer) and the host can close the write window early (full bracketing, scoring and pacing rules in [clapback_spec.md](clapback_spec.md)). Bank lookups are NSFW-gated on the channel (`channel_allows_nsfw`), so NSFW prompts only surface in age-gated channels.

**Pacing and endings of the three reactive round games** (`games/utils/round_pacing.py`, shared by WYR, NHIE and MLT so the rules cannot drift; vote-games-52/53, discovery-1/3, platform-23). Each launch resolves a `(round_seconds, max_rounds)` pair — a slash argument or schedule option wins (even an explicit 0), else the dashboard dial on the game's panel (`round_seconds` default 0 = host-paced, `max_rounds` default 10; 0 = no cap), clamped to 0–300 s and 0–50 rounds — and stores it in the payload with `scheduled` (the scheduler stamps `scheduled: true` on its option bag; feature rotation launches as host 0, which counts the same). Each round records `opened_at`; a timed round shows **⏱️ Next Round — Auto-advances `<t:…:R>`** and closes itself on `asyncio.wait_for` (Two Truths & a Lie's pattern) unless Next, End or `force_end_active_game` (which pokes the view's `_advanced_event`) gets there first — Next is an early skip, never removed. After a restart the timer resumes for the remainder (at least 5 s). **Next** is host / mod / the configured Game Host role (`games_editor_role`, the same role that may move other players); on a **scheduled** launch anyone who voted this round may also press it once the round has been open for the round timer — or, host-paced, 90 s (`SCHEDULED_NEXT_UNLOCK_SECONDS`) — with the refusal naming the unlock moment, so an absent schedule creator cannot stall round 1. The round that reaches `max_rounds`, the host's **🏁 End Game** (host / mod / Game Host, behind the usual confirm), pressing Next on a game past the 24 h line (vote-games-59 — it used to be a bare guild-0 end that paid nobody and dropped the round), MLT's roster falling under 2, and `/games end` all end through **one paying path per game** (`_finish_game`: `end_game(bot=, player_ids=…)` with a `reason` of `ended`, `round_cap`, `expired` or `too_few_players`) after writing the open round — WYR posts the **Game Over** card (rounds played, total votes, the most divisive question and its split; vote counts only — who voted is each voter's own to show, see below), NHIE resolves the round (guilt, hearts) and posts the **guilt board** ("Game over — here's the final guilt board"; its roster is the lives tracker plus every voter, so a `lives:0` game pays too), MLT tallies the open round, posts its results, banks the crown and posts **Final Standings**. Votes are written to the payload on every press (`persist_votes`, through `modify_payload`), not only on Next, so a restart mid-round rebuilds the tally it shows (vote-games-58). **WYR votes are anonymous by default and each voter's own to disclose** (vote-games-61, 2026-09-04): the round board's **👀 Show My Vote** (any voter, after voting; a non-voter is told to vote first) names the presser beside their pick — each side lists its shown voters and counts the rest as `+N anonymous` — and the choice rides in the round's `shown` list beside `a`/`b`, so a rebuilt view still names them. It replaces the host/mod-only **Reveal Voters**, which named the whole room and refused everyone else (five refused presses in one prod game); a mod who needs to know who voted reads the vote rows in the Anonymity Audit, which is why a self-reveal writes no `voters_revealed` row. The footer badge reads *Anonymous unless you Show My Vote* rather than a bare *Anonymous* (`payload["anonymous"]` is always `True` — there is no named-round launch option). **Every Pose queue holds 15** (`_MAX_QUEUED_QUESTIONS` / `_MAX_QUEUED_PROMPTS` / `games_nhie.logic.MAX_QUEUED_STATEMENTS`, the last added 2026-09-04 — NHIE's queue was unbounded, vote-games-62); the sixteenth pose is refused with "The … queue is full (15). Let some play first!". `/games end` on these three types calls the cog's `end_with_recap` (looked up by cog name, `RECAP_ENDING_COGS` in the config cog) instead of the red Force-Closed card; an MLT lobby that never started has nothing to recap and force-closes as before.

### Anonymous-submission games

**Anonymous Truth or Dare (FFA), Hot Takes, Fantasies & Dealbreakers, Anonymous AMA** post submissions to the play channel without the author's name attached. Every such submission is recorded in `anon_audit_log` — who posted it, when, and a pointer to the message — and is reviewable on the admin dashboard's **Anonymous Features** audit panel (`anon_audit_spec.md`). If an audit channel is also configured, the submission is mirrored there with the original author visible, so staff watching Discord see it without opening the dashboard. **All three member-written games say so on their own boards** (anon-tail-75, 2026-09-04): FFA's reply help, the Hot Takes lobby and the Fantasies panel each carry the line *mods can still see who sent it*, next to a how-to-play paragraph in the embed itself rather than only behind the Help button.

**FFA embed mode** (`/games play ffa`; anon-tail-69/70/76, 2026-09-04) serves **truths by default** — `kind:` defaults to `truth` on the reply-button command (`EMBED_DEFAULT_KIND`) and a launch that names no kind, from the scheduler or rotation, draws a truth too, because a third of the bank's dares ask for a voice note, photo, video, nickname or status change that an anonymous text box cannot deliver; `kind:dare` / `kind:random` and the banner card (`/games play ffa_banner`, open chat, still random) draw them on request. The command's tag pre-check passes the kind into `has_matching_questions(kind=…)`, so `kind:dare tags:lily` where every lily row is a truth is refused at the command with the guard's `no_tag_match_message` rather than launching, finding nothing and blaming channel permissions. Each posted prompt's `prompts` entry records its `repliers` (`games_ffa.logic.note_reply`, de-duplicated) beside its `reply_count` — **recorded for payout only**: `ffa` is in `game_roster.ANON_ROSTER_TYPES`, so the per-reply session touch, the Close and the sweep all land the game in the game-night session without its roster, and `/recap` (which names session players) never lists a replier — and the game finally **ends**: the host's or a mod's **🏁 Close** (row 1 of every prompt message, behind the usual confirm) runs `finish_ffa_game` — every prompt message's buttons come off, the **Anonymous Truth or Dare — Recap** card lists replies per prompt, the 🔥 busiest prompt, total replies and the count of distinct repliers (no names, the recap is as anonymous as the replies; "no replies came in" is a one-liner instead), the prompts' `confession_emoji_assignments` / `confession_pools` rows are cleared (`confessions_service.clear_anon_identities`), and `end_game(bot=, player_ids=repliers, reason='ended')` pays. `ffa` left `game_roster.NO_ROSTER_TYPES` for this: `_ffa` rebuilds the same roster from the payload, so the 24h sweep and `/games end` pay repliers too, while a banner card (no `prompts`) yields nobody and — its launch-time `update_session` gone — never opens a game-night session. The alias map itself now has a clock: migration 211 adds `created_at` to `confession_emoji_assignments`, `purge_old_thread_posts` sweeps it at the same seven days as `confession_threads` (pre-migration rows default to 0 and go on the first sweep — a thread older than a week has already lost its routing row), and `purge_user_data` deletes a member's alias rows outright (`docs/data_register.md`). `hottakes` runs in two phases (submit, then a 5-step temperature vote per take with a live results bar); the public "🔥 Hot Takes voting is starting!" heads-up posted when the host opens voting names nobody — it counts the takes and is sent with mentions disabled, because the submissions are anonymous and until 2026-09-02 it @-mentioned every submitter (a lone take was attributed outright). **Start Voting needs two takes** (`games_hottakes.logic.MIN_TAKES`, anon-tail-72): one take is not anonymous — the room knows whose it is — and the refusal says so. Start Voting records the phase on the live row (`state = 'playing'`), and boot recovery branches on it: a lobby (still `joining`, no results) gets its submit view re-registered on the anchor message so the host still presses Start Voting, while a game in voting is re-driven from the first take without a persisted result. Until 2026-09-04 the phase was never written and recovery keyed on the take count alone — an empty lobby was left with dead buttons until the sweep, and a lobby holding any take was force-started into voting on restart (platform-29, anon-tail-66). The lobby carries a host/mod **Cancel Game** button behind the usual confirm popup; a cancelled lobby has no roster, so it archives with `reason = 'cancelled'` and pays nobody. **Each take is paced** (anon-tail-71/74, 2026-09-04, reusing `games/utils/round_pacing.RoundPacing`): the launch resolves `round_seconds` through `resolve_pacing` — a slash `take_seconds:` or schedule option (even 0) wins, else the **Seconds per Take** dial on the Hot Takes dashboard page (`hottakes`, one dial, no bank), else `DEFAULT_TAKE_SECONDS` (45); 0 is host-paced. A timed take shows the shared **⏱️ Next Round — Auto-advances `<t:…:R>`** field and closes itself when the clock runs out; it also closes the moment **everyone the take is waiting on has voted** (`active_voters`: every submitter plus everyone who has voted on an earlier take this game, minus the take's author; `everyone_has_voted`), and **⏭️ Next Take** (host / mod) is an early skip rather than the only way on. A take's **author cannot rate it** — the same "❌ You can't vote on your own entry!" line Fantasies uses; in a two-voter room one 🔥 self-vote had decided the winner bonus. Hot Takes is a **lobby game** since the same date (`LOBBY_GAME_TYPES`; button *Start Voting*; floor 2, its roster being the distinct submitters written to `participants` by `add_take`), so `start_in:` puts a countdown on the lobby, the host nudge, the idle-lobby dials and the Game Night ping apply, and a scheduled lobby nudges its creator. `fantasies` is multi-round; each round runs Submit → Reveal → Same/Not-for-me per entry, and the host can keep running rounds before pressing **End Game** on the control panel (host or mod, confirm popup): that disables whatever the round loop is blocked on (an entry mid-vote is dropped, as on `/games end`), posts the recap with the payout footer — or a one-line "nothing to recap" when no entry was ever voted on — and ends the game with `bot=`/`player_ids=` so the faucet pays entry authors plus every voter (`games_fantasies.logic.roster_from_results`, the same two payload fields `game_roster` reads for the sweep). Until 2026-09-04 the panel offered only Start Round and Help: the recap builder was dead code and the only ways out were `/games end` and the 24h sweep (anon-tail-65). A round that closes with zero entries is the skip — the panel stays live and the notice points at Start Round or End Game. **Each entry is paced the same way as a Hot Takes take** (anon-tail-71): `round_seconds` from a slash `entry_seconds:` / schedule option, else the **Seconds per Entry** dial on the Fantasies dashboard page (`fantasies`), else `DEFAULT_ENTRY_SECONDS` (45; 0 = host-paced); the countdown field, the vote-complete close (this round's submitters plus earlier voters, minus the entry's author) and Next-as-skip are identical. Fantasies is a **lobby game** too: the panel opens as `state = 'joining'` (button *Start Round*, floor 1 — nobody joins a Fantasies panel, so the idle hour closes one whose host never started a round), `start_in:` advertises the first round, and the first Start Round moves the row to `playing` so the sweep leaves a live game alone. The category is **chosen by button** — the round's submit message carries *Submit a Fantasy* and *Submit a Dealbreaker*, each opening a modal holding only the entry box. It used to be typed into a text field beside the entry, and a word the parser didn't recognise closed the modal with an error, discarding up to 500 characters the member had just written.

`ama` is the largest and longest-running game, with **two independent axes**:

- **Content mode** — `unfiltered` (questions post immediately) or `screened` (host approves via DM before the question appears; rejected questions never post and never pay out quest credit).
- **Format** — `hot_seat` (one person answers at a time; the seat rotates) or `panel` (ask anyone who has opted into the panel, chosen from a dropdown).

AMA carries a per-question lifecycle (pending → answered / passed / rejected / expired), a screened-mode approval queue, DM notifications to the original asker when their question gets a reply (the DM names the channel and carries a jump link to the answered Q&A card, so the asker lands on their own question rather than at the bottom of the channel), a retention window for unanswered screened questions, and stale-target guarding: a modal submitted after the hot seat rotated (or after the target left the panel) is rejected with a "please try again" notice. **Endings** (social-prompt-33, 2026-09-04): the host or a mod presses **🏁 End AMA** (confirm popup) and the game closes through `AMAView.close_now` — bottom bar removed, every still-open question card retired with an *AMA ended* footer (social-prompt-43; Reply / Pass and a reply modal on a closed game answer "This AMA has ended."), the recap with its payout footer posted, and `end_game(reason=)` paid for the askers and hot seats. `/games end` (via `AMACog.end_with_recap`) and the 24h sweep (`expiry_service._close_through_live_view`) go through the same `close_now`, so the recap posts on every end path; until then it was reachable only from the feature rotation and the sweep ended an AMA silently. **The hot seat rotates on answered questions, not asked ones** (social-prompt-34): a question posted no longer moves the turn along — answering or passing it does (`after_question_resolved`, only when the resolver is the current seat), so a seat is never emptied with cards still open; the turn length is the panel's **Questions per Turn** dial (`questions_per_turn`, default 4, clamped 1–20, stored in the payload). In panel format the presser is dropped from the ask picker (no planting a question on yourself) and exactly one remaining candidate opens the modal directly rather than a one-name dropdown. **The hot-seat announcement pings the panel's Hot-Seat Ping Role dial** (`hot_seat_ping_role_id`, default none, allow-listed explicitly; social-prompt-41) — not a role looked up by the name "AMA". Because that dial ships unset, a guild that already had an `@AMA` role would have gone quiet the day the dial replaced the lookup, so the dial is **seeded from such a role once** (`games_ama.ping_role_service`, ship review 2026-09-05): on the first launch that finds the key absent from the stored option bag, a role named "AMA" (case-insensitively, exact name) is adopted and written to the dial, and if there is none the key is written empty so the look never repeats. The key's *presence* is the marker, so a dial an admin cleared to (none) — which writes the key — stays cleared. **Screened approval never expires** (social-prompt-35): `ScreenedQuestionView` is persistent, the host's DM carries the question text (it never did), its message id is stored on the question (`host_dm_message_id`) and `recover_game` re-registers the buttons against it; pressing Approve after the game closed retires the DM instead of posting. **The seat's hour survives a restart** (social-prompt-42): `hot_seat_started_at` is stamped on every seat change and `recover_game` re-arms the timer with what is left (at least 5 s). **The timed-out rotation never cancels its own task** (games deep review follow-up A1, 2026-09-05): the hour timer's rotation re-arms (or, with nobody queued, clears) the timer from inside the timer's own task, and `_cancel_hot_seat_timer` skips `asyncio.current_task()` — until then the cancel landed on the rotation's next await, so the *A new host … is in the hot seat!* announcement, the board refresh and the empty-queue `hot_seat_id = None` write were silently lost (the same self-cancel class as Mahjong's phase timers). **A close is idempotent** (A3): `_do_close` returns once `_closed` is set, and a card resolved after 🏁 End AMA confirmed (a Reply modal that passed its check before the confirm) refreshes the board but never posts a second recap. Every embed prints the mode as **Unfiltered** / **Screened** (`logic.mode_label`; social-prompt-44). The retired AI idle-question helpers are gone (social-prompt-48); the `asker_id > 0` filters stay as a cheap defence against a malformed entry.

### Pool / pairing / draft games

**Spin the Compliment, Marry-Fornicate-Kiss, Two Truths & a Lie** open with a join-pool phase and a host-only "close pool" button that transitions to play; **Truth or Dare (traditional)** has no such phase — opting in and play are one board, and its row stays `joining` from open to end (trivia-tail-98). `compliment` requires 2 players and produces a giver → receiver pairing with no fixed points; the public ping is auto-deleted after 15 seconds, and the pairings card names members through a `name_fn` (the mentions live in the ping's content). Its lobby has separate **Join** and **Leave** buttons (social-prompt-46; the old single Join was an unlabelled toggle). **Close & Generate opens a ten-minute wrap-up rather than ending the game** (social-prompt-39, 2026-09-04): the row goes to `state = 'wrapping'` with `generated_at` / `wrap_nudge_at` / `wrap_ends_at` in the payload; at five minutes the pairings are reposted with a ✅ on every giver seen delivering — a message of theirs in the channel since `generated_at` that replies to, or @mentions, their receiver, read from the archive's `messages.reply_to_id` / `message_mentions` metadata, which is recorded whatever the content-storage level — and the stragglers get one nudge (nothing is posted when everyone has delivered); at ten minutes the **Wrap-Up** card says how many compliments landed, carries the payout footer, and *that* is when `end_game` pays the pool (`delivered` is archived in the payload). The wrap runs **once**: the timer and the host's own `/games end` both call `finish_wrap` and both see a live row, so the first one to get there claims it in the payload (`claim_wrap`, under the game's payload lock) and the loser returns without reposting the card or paying the pool a second time (ship review, 2026-09-05). A game found still live at boot means the winner died before `end_game` archived it, so recovery drops the stale claim before re-arming the wrap. A restart re-arms the wrap from the epochs (`recover_game`, registered like the other lobby games — the old `cog_load` re-registration is gone); `/games end` during the wrap finishes it on the spot through `end_with_recap`, and a lobby still takes the force-close. The Wrap-Up's **🔁 Spin Again** (host or mod) relaunches under the presser through the launch guard. `mfk` requires 4 (and caps the pool at 25, since the assignments embed adds one field per player and a Discord embed holds at most 25 fields) and gives each player a random 3-name sample from the pool (never themselves); `options:` lets the host override the three category labels. Both consult the **no-contact list** at close: a blocked pair is never giver→receiver in either direction (a pool with no safe pairing gets the ordinary "Need at least 2 players" refusal), and blocked MFK members are dropped from each other's sample, which just shows fewer names — see `docs/no_contact_spec.md` for the disclosure shapes. `traditional` toggles each player into any combination of four category pools (SFW Truth, SFW Dare, NSFW Truth, NSFW Dare) and weights target selection by least-asked count so one chatty player doesn't soak up turns; its **Ask Question** button first drops every NSFW preference when the channel is no longer age-restricted (`filter_nsfw_prefs`, safety-sweep-10 — a room that lost its flag mid-game stops serving NSFW at once), then excludes the presser's no-contact partners from the target pool before that weighting (the presser, not the host — a mod can ask too), and reuses the "All player/category combinations have been asked!" reply when only they remain. Since 2026-09-04 (trivia-tail-89 / discovery-9) Ask Question opens the question box **pre-filled from the bank** (`get_traditional_question` for the chosen category, `TextInput.default`) so the host sends, edits or replaces it — a question sent unchanged counts as a bank ask in the recap; **Write My Own** opens the same box empty. The asked history is **per pass** (`asked_key`: pass 1 keeps the legacy `uid:cat` key, pass *n* appends `:n`): when every declared (player, category) pair on the current pass has been asked the channel hears `🎉 Pass 1 complete — …` and the next Ask rolls the payload's `pass` forward and picks again, so the game never dead-ends; the least-asked weighting counts every pass. The modal's record goes through `modify_payload` (a category toggle landing while the box was open is kept). Its host-only **Bank Round** button deals every opted-in player one question from the web-managed bank; bank questions share the same per-(player, category, pass) asked history as host-written ones, so each player is served at most once per opted-in category per pass and re-pressing after new players join only serves the newcomers (the host summary reports how many already-asked players were skipped). Like the other bank-backed games, the draw itself is round-robin (least-recently-served row first) so a category's pool doesn't repeat a question across separate games until every row in it has been served. Its host-only **End Game** button posts the recap embed and pays the room; it was missing until 2026-07-29, which left the recap and the payout unreachable (see "Which end paths pay" below). The game also **ends itself**: the Traditional panel's **Quiet Minutes Before Auto-Close** dial (`idle_minutes`, default 20, 0 = off) is copied onto the payload at launch with a `last_activity` stamp that every toggle, question and bank round refreshes; the host view arms a task for the remaining window (re-armed from the payload after a restart), re-reads the payload when it fires, and closes through the same `_do_close` as End Game with a one-line note on the recap and `reason='idle'` — so a room that went quiet pays and archives within the window instead of waiting for the 24-hour sweep (trivia-tail-84: 18 of 19 prod games were swept). This is the one named exception to the no-inactivity-close non-goal (see Non-goals). `twotruths` collects three statements + the lie index per player via a components-v2 modal — the full prompt renders as static text inside it (the 45-char title used to truncate it), and the prompt is repeated on every round's guess embed for mid-game joiners. Statements are shuffled at display time and the room votes per player. Players can resubmit (the modal prefills their previous entry) via **Submit Statements** or the mid-game **Join / Edit** button until their own round is revealed; after that, statements are locked (`played` list in the payload). Only the lobby message's player roster is ever edited on submit — the modal never touches the active guess embed (2026-07-20 fix: a mid-game join used to overwrite statement 1's field). Rounds advance on the host's **Next** button, or automatically when the dashboard `vote_timer` option is set (>0 seconds; default 0 keeps host pacing). The recap's "fooled the fewest" award is **🪞 Open Book** (with fooled count); Best Liar and Best Guesser both earn the economy game-win bonus.

### Sequential storytelling

**Story Builder** builds a story sentence-by-sentence; the default "blind" visibility shows only the previous sentence in the modal while `full` shows everything so far. Max 30 sentences, default 10. Each turn posts one panel — the ping plus Write/Skip/Leave buttons — and that panel is **deleted when the turn resolves**, the way Price is Right deletes its host prompt; it used to be edited to a disabled state and left in place, so a 5-player 4-round story interleaved its own text with twenty spent panels. **Pacing** (anon-tail-73/77/78, 2026-09-04; rules in `games_story.logic`): a turn is **120 s** (`DEFAULT_TURN_SECONDS`, was 300 — one AFK writer cost two five-minute holes in a fifteen-minute game); **Skip** is the host's or a mod's at any time and **any writer's** once the turn has been open 60 s (`WRITER_SKIP_AFTER_SECONDS`, the refusal names the unlock moment), so an AFK host no longer stalls the story; a writer who misses **two turns in a row** (timed out, dismissed the box, or was skipped — `note_turn_outcome` / `should_drop_writer`) is **dropped from the rotation** with a channel notice, and the remaining writers start a fresh lap (`consecutive_skips` resets, so a shrunken rotation is not ended by the leaver's misses; an all-miss lap still ends the story, and so does an emptied rotation); **🚪 Leave** on the turn panel takes a writer out after the current turn (`rotation_after_turn` keeps the next writer's place; a leaving current writer is also a skip). The reveal pays `roster_for_payout`: everyone who joined, minus writers who left without writing a line (the turn loop persists the leavers as `payload['left']`, so the sweep and `/games end` — `game_roster._story` — pay the same room) — a writer dropped for missing turns stays paid. The row's host stays the host: a mod pressing Start on the host's behalf used to overwrite `host_id` and take the host's Skip away. The sentence modal carries the turn's timeout and hands its sentence to the turn view from `on_submit`; the button callback no longer awaits `modal.wait()`, so a dismissed box leaks nothing.

### LegitLibs

`legitlibs` runs a Mad-Libs-style template fill in one of **two** modes. **Classic** fills blanks one at a time round-robin, with a volunteer rescue path when a player times out. **Quiplash** has every player fill in parallel and reveals one filled version per player at the end. Templates are **per-guild** (`legitlibs_templates.guild_id`, migration 124): a guild draws its own templates plus the shared **global pool** (`guild_id = 0`), and an admin can promote a template to the pool — or claim it back to the server — from the dashboard (per-row *Make global* / *Make server-only*; the starter pack ships global). Templates are picked by tier (1 Flirty → 4 Unhinged, default 2) with optional tag filtering, and the picker avoids the five most-recently-used templates per guild. Each channel has a `max_tier` cap (dashboard-managed); requesting a higher tier plays at the cap, and the slash entry tells the host so ephemerally (`classic_logic.tier_clamp_note`, worked out before the defer — the modes clamp again for the headless doors but only log; until 2026-09-04 nothing sent the note the edge-case table promised, trivia-tail-93). Per-blank fill prompts and example text are resolved through a fallback chain (most specific → bare part-of-speech) so even an under-specified template still renders a useful modal.

**Player range is mode-aware** (`validation.player_range`, trivia-tail-83). The dashboard derives a template's stored `player_min`/`player_max` from its blank count (each player fills 5–10 blanks) and re-derives it only when the blanks actually change, so the starter pack's authored range survives a title edit. That range is a **Classic** fact — round-robin hands out the blanks, so a 5-blank story really is a one-player Classic — and Classic's lobby enforces it. **Quiplash** has everyone fill every blank, so it ignores the stored range and takes a fixed 2–12 (`QUIPLASH_PLAYER_MIN`/`MAX`); before this, every 5–9-blank template was a one-player Quiplash lobby and nothing could seat more than five. The dashboard card and the editor show both ranges, and the list route carries `quiplash_player_min`/`max` so the panel never re-derives the constant.

**A round is short and loops.** Both modes give the room **two minutes** to fill (`FILL_TIMEOUT`, was five; the loop already ends early once everyone has submitted), Classic's rescue path is unchanged (45 s claim, 2 min rescue fill), and the last reveal message carries a **🔁 Another One** button (`views.RecapView`, host or mod) that draws the next template from the pool at the same tier, mode and tag through the shared launch guard — attached only after `end_game` has run, so the guard sees a free channel (trivia-tail-90). It never re-uses a template id, so the recent-use window steers it away from the story just played; when the pool is exhausted the press is answered ephemerally. **The reveal pays the people who put a word in, not everyone who pressed Join** (trivia-tail-95): Quiplash pays `quiplash_logic.payout_roster` (the complete submitters), Classic pays `distribution.unique_contributors` (whoever filled a blank, rescue included); `player_count` on the history row stays the joined roster.

### Start countdown + host nudge

Nine games open a join lobby and wait for a human to press the start button — **Clapback, Spin the Compliment, Marry-Fornicate-Kiss, Most Likely To, Mt. Rushmore Draft, Story Builder**, and since 2026-09-04 **Hot Takes** (*Start Voting*), **Fantasies & Dealbreakers** (*Start Round*) and **Name Your Price** (*Start*) (`LOBBY_GAME_TYPES` in `games/constants.py`; anon-tail-72, trivia-tail-85). Only these take `start_in:[1-60]`. Two more games — Two Truths & a Lie and LegitLibs — also open a lobby and wait on a host press, but were left out and take no `start_in` (see `docs/plans/game-start-countdown.md`); every remaining party game posts its first prompt the instant the command runs, so it has nothing to count down to. `start_in` stamps a `start_epoch` in the game payload and renders it as a live Discord relative timestamp in an **⏰ Starting** field on the lobby embed, refreshed on every join/leave edit. For most it is **advertising, not automation** — the game does not auto-start, and the host still presses the button. **Clapback and Name Your Price are the exceptions** (clapback-8, trivia-tail-85, 2026-09-04): see *Countdown auto-start* below.

When the advertised moment arrives, `game_start_ping_service` posts a nudge in the game's channel mentioning the host by name and by button (`⏰ @host — time to start **Mt. Rushmore Draft**! Hit **Start Draft** when everyone's in.`), allow-listing only that one user. A **dashboard-scheduled** lobby game gets the same nudge the moment its lobby lands, aimed at whoever created the schedule — otherwise a scheduled lobby sits there with nobody aware a press is pending. Scheduled lobby-less games are never nudged; they self-run, and neither is a scheduled lobby of a game that starts itself.

**Countdown auto-start** (clapback-8, 2026-09-04). A lobby game whose cog registers a starter in `bot.lobby_auto_starters[game_type]` (`(row, payload, channel) -> bool`; Clapback and Name Your Price — `ClapbackCog.auto_start`, `PriceCog.auto_start`) is **started by the same sweep** at `start_epoch` when the roster is at or above the game's floor (`auto_start_due`: countdown reached, `lobby_roster_size >= lobby_min_players`, no earlier attempt flagged `auto_start_failed`). The starter re-reads the roster, applies the Start button's own gates (Clapback's no-contact `playable_players` floor and `MAX_PLAYERS`), stops the lobby view and retires its buttons exactly as a press would, runs the shared `_begin_game` (scoreboard seed, state → `playing`) and spawns the game loop as a background task so the sweep is never held for a game's length. The lobby embed's countdown field says so: `<t:…:R> — on its own, once 3 have joined`. Short of the floor at the moment, the host is nudged **once** with what the lobby is waiting on (`build_short_roster_nudge`: `⏰ @host — **Clapback**'s countdown is up, but only 2 of the 3 it needs have joined. It starts on its own the moment 3 are in — with fewer than that it closes after 60 minutes.`) and the idle-lobby close below runs from the advertised start as before — but the game still starts itself the tick the floor is reached after that (`auto_start_due` is deliberately not gated on `start_ping_sent`). A starter that returns False (the no-contact floor refused) falls back to the ordinary "time to start" nudge, and Start then gives the host the usual refusal line; one that raises is flagged `auto_start_failed` and never retried. A **scheduled** lobby of such a game therefore runs with nobody at the keyboard: the scheduler stamps `start_in = SCHEDULED_AUTO_START_MINUTES` (10) when the schedule's options name none, keeps a schedule's own `start_in`, and skips the creator nudge for it. Games without a starter keep the press-the-button contract above unchanged.

**The Game Night ping** (discovery-2 / clapback-11, decision D4, 2026-09-04). A member launch used to post nothing but the board, so a lobby was invisible outside its channel. The same sweep now posts **one** line per lobby, the first tick it sees the lobby's board (`message_id` written — every DB-backed launcher does that before returning), mentioning the guild's opt-in **Game Night** role: `<@&role> 🎮 A **Clapback** lobby just opened — it starts <t:…:R>! Jump in: <jump link>`, as message `content=` with `AllowedMentions(roles=[role])` and embeds suppressed, never inside an embed. Platform-level on purpose: every `/games play` launch of a lobby game and every scheduled one gets it with no per-cog edit; lobby-less games (which post their first prompt at once) are out of scope. The role is `feature_roles.GAME_NIGHT_PING` (config key `game_night_ping_role_id`, the **Game Night Ping Role** dial on **Games Global Config**, `GET/PUT /api/games/config/lobby`), provisioned on first use through `ensure_config_role` like every other ping role: never touched ⇒ `@Game Night` is created on the next lobby; a stored "(none)" ⇒ opted out and the sweep stays silent (`resolve_game_night_role` returns `(True, None)`; an unreachable guild returns `(False, None)` and the lobby is looked at again next tick rather than flagged). Members pick the role up through Discord Onboarding (`opt_in=True`, so the Onboarding page offers it). `game_night_pinged` in the payload is the once-only flag, and both senders take it as a **claim** (`claim_game_night_ping`, an UPDATE that matches only while the flag is unset) *before* they send: a schedule with **Announce When It Starts** ticked claims it before its own announcement, so its line (with whatever role it names) stands in for the sweep's. The claim, not the write, is what makes the ping once-only — the two run on separate clocks and were both able to fire for one opening, the sweep reading a row at the top of its tick that the schedule flagged moments later (ship review, 2026-09-05); whichever loses the claim now stays silent. A launcher that keeps its round in memory and registers no row (risky_roll) has nothing to claim, and announces (`no_row_wins`). The ping is recorded through `ping_tracker_service.record_game_start_ping` against the lobby it advertised, so the Ping Response report can count who joined. Per-launch suppression (a `ping:false`-style option) was **not** built: nothing cheap exists at the platform level, and it would need a parameter on six slash commands.

A schedule row with **Announce When It Starts** ticked adds one more message, and the order is **board → announcement → nudge**. The announcement fires *after* the launcher returns, not before it, because it carries a jump link to the board and there is no board to link at until the launcher has posted one (todo #97) — landing people in the channel to hunt for the game was the complaint. Every DB-backed launcher writes `message_id` before returning, so `get_active_game_by_id` reads it straight back; `risky_roll` keeps its round in memory and registers no row, so it announces the bare line with no link rather than a URL with a missing segment. The ordering also means a launch that fails announces **nothing** — the old order pinged a role about a game that then never appeared. That leans on `launch` returning `None` for *every* failure, which is a contract worth stating: `wyr` and `nhie` run their first round inside `launch`, and an empty question bank posts its notice, calls `end_game` and unwinds **normally** — so both check that their `games_active_games` row survived the round and return `None` when it didn't (`tests/cogs/test_games_launch_contract.py`). Without that they reported `launched` for a game that had already ended, putting the ping directly under the "bank is empty" notice. The configured role is allow-listed explicitly (`AllowedMentions(roles=[Object(id=…)])`, `none()` when unset), and the send suppresses embeds so the link doesn't render a preview of a board one message above it.

The nudge is driven by a 15-second poll over open lobbies rather than a per-lobby timer, so it survives a restart: a bot that was down across the start time nudges late on its next sweep instead of never. A game started early, cancelled, or timed out leaves the `joining` state and drops out of the sweep, so a running game never gets a "time to start". Each lobby is nudged at most once (`start_ping_sent`), and a lobby whose channel has become unreachable is marked rather than retried every tick.

**Idle lobbies** (discovery-6, 2026-09-04). The same sweep applies two per-guild dials from **Games Global Config → Idle Lobbies** (`config` keys `games_lobby_idle_nudge_minutes`, default 20, and `games_lobby_idle_cancel_minutes`, default 60; 0 switches a step off; `GET/PUT /api/games/config/lobby`). A `joining` lobby opened **without** a countdown is nudged once after the first window — the same tap on the shoulder a countdown lobby gets at its advertised start, naming the button and, when the close is on, the deadline (`⏰ @host — **Story Builder** has been waiting 20 minutes. Hit **Start Story** when everyone's in — with fewer than 2 players joined it closes on its own after 60 minutes.`). After the second window a `joining` lobby that still holds **fewer than its game's minimum roster** (`LOBBY_MIN_PLAYERS` in `games/constants.py`, mirrored from the cogs' own floors — a test pins them — or the higher floor an mlt / rushmore payload names) is closed through `end_game(reason='lobby_timeout')` with **no payout** and its lobby message is retired (`⌛ **Lobby timed out** — …`, components removed, the in-memory view stopped). A countdown lobby's hour starts at its advertised start rather than at open; a lobby with enough players to start is **never** closed by the sweep — that is the host's call, however long they sit on it. Before this, only Clapback's own 10-minute view timeout closed anything; the other five lobby games and every lobby that survived a restart sat until the 24-hour sweep. This is a pre-game close of a lobby that never filled, not a mid-game inactivity timeout (see Non-goals).

**Live game boards** (2026-09-10; Name Your Price joined 2026-09-11). A live board buried under chat is easy to lose track of — nothing re-surfaces it today except a full redraw. The **Live Game Boards** dial on **Games Global Config** (`config` key `games_board_sticky_enabled`, default **off**, `GET/PUT /api/games/config/board-sticky`) is a single per-guild knob covering every game that wires itself to it — one dial, never a per-game override. Two games have: **Mt. Rushmore Draft**'s draft board, which stays sticky for the length of the draft, and **Name Your Price**'s submission board, which is sticky for each round's submission window (a fresh board opens every round, so a fresh panel does too). Off is truly inert: the dial is read exactly once, the moment a board is first posted, and a dial-off game behaves exactly as before (an in-place edit of the previous message, no `StickyPanel` ever constructed). A mid-game flip never touches a board already running — only the next one sees the new value.

The wiring lives in `services/game_board_sticky_service.py`, not in the cogs: `board_sticky_enabled`, `board_location`/`set_board_location` (the synchronous id hooks), `build_board_content`, `make_board_panel`, `open_game_board` and `retire_game_board`. Both cogs went through a hand-rolled copy of all of it first and the two copies were identical apart from the view's type name, which is what moved it into the service; a third adopter supplies a view and two call sites and nothing else. The view contract is the `LiveBoardView` protocol — `game_id`, `guild`, `_build_embed()`, plus the `_panel` and `_board_retired` attributes the wiring sets.

Both reuse `core/sticky.StickyPanel` (never a parallel implementation) with **one instance per live board**, keyed by `game_id` — a guild can run several games in different channels at once, so a single shared panel would collide. `load_ids`/`save_ids` read and write the game's own row in `games_active_games` (`channel_id`/`message_id`, the same columns `update_game_message` and the busy-check's jump link use, so a repost can never drift out of step with what `/games end` sees); they are synchronous because `StickyPanel` calls its id hooks off-thread, which is why they live in the service rather than in `game_manager` alongside that table's async accessors.

Two lifecycle rules are load-bearing, and both are needed — the first alone is not enough. `build` **raises** `RuntimeError` rather than returning `None` once a board is retired: `StickyPanel._place_locked` does not check its build result, so `None` would explode inside core (`economy_cog._build_auction_panel` is the established idiom). The flag it checks is `_board_retired`, deliberately distinct from each game's pre-existing `_closed`, which is set one render *earlier* for the legitimate "complete" frame that must still go through. And `retire_game_board` calls **`forget()`** as well as `cancel_all()`, mirroring `auction_views._release_panel`: an `on_message` already in flight when the game ends can otherwise still read the panel's cached ids and schedule a restick nothing cancels, reaching the refusal above — which core logs as an ERROR traceback for a perfectly ordinary game ending. Because the callers' redraw seams can also race teardown, they swallow that refusal rather than let it escape.

Nothing is posted outside `place()`, so the old message is never deleted explicitly: `board_location` reads it straight out of the game row, `place()` treats it as "the old panel" and removes it **after** the new board is safely up. Deleting first would invert post-before-delete — a placement failure would leave the game with neither the old message nor a board.

Teardown is called at every point a board's life ends: for Rushmore a `try/finally` around both draft loops (so natural completion and a forced `/games end` alike) plus a guard for a failure that never reaches a loop; for Price the disabled frame, a host's own End Game button, and a forced end — idempotent, since the round loop and `end_early` can both reach it. Price's `retire_game_board` also hands back wherever the board actually ended up, because it goes on being edited (reveal, then the next round) and a repost may have moved it since it was opened. `on_message`/`on_guild_channel_delete` are forwarded from cog-level listeners to every live board's panel, and `cog_unload` calls `cancel_all()` on each before clearing.

### Scheduled launches

Schedules (`games_scheduled`, the Game Scheduling panel, `/api/games/schedule`) are polled every 60 s by `scheduled_games_service`. A due row is checked in order: lateness, channel reachable, enabled dial (against the base type for a display variant), the feature rotation's hidden state, and **channel busy**. A busy channel makes the row **stay due and retry every poll** — a one-time row until its `giveup_at`, a recurring row until the slot is `GIVEUP_GRACE_SECONDS` (2 h) old — and the retry is recorded as a run (`last_run_at`, `last_status = skipped_active`). When the grace runs out a one-time row is marked `skipped_giveup`; a recurring row rolls to its next slot as `skipped_active` when a retry happened *within* that slot, else `skipped_late` (the bot slept through it). Until 2026-09-04 a recurring row rolled the moment the channel was busy, so a member-opened round overlapping the slot by a minute cost the whole day — prod's daily Risky Rolls was skipped on 09-02 for a round that closed 21 minutes later (platform-24). A successful launch stamps `last_launched_at` (migration 205), the one column that says when a schedule last *produced* a game; the panel shows it ("Last launched: …" / "Never launched yet") and, while a slot is retrying, "⏳ Channel busy — retrying until …".

The panel tags every schedulable game with how it runs (`hosting_kind` in `games/constants.py`, served on `/api/games/schedule/options` and each row): **Self-running** (`SELF_RUNNING_GAME_TYPES`: ffa, ffa_banner, risky_roll, photo — posted and finished with nobody at the keyboard), **Self-running with a round timer** (`TIMER_RUNNING_GAME_TYPES`: wyr, nhie — self-advance and end at the round cap only when a round timer is set; host-paced they show one question and wait), **Starts itself after a countdown** (`AUTO_START_LOBBY_TYPES`: clapback, price — the lobby games whose cog registers a `lobby_auto_starters` entry; a scheduled row stamps a 10-minute countdown and the start-ping sweep starts the game when its floor has joined — three, or two for Name Your Price — see *Countdown auto-start*; the schedule creator is still nudged when the lobby lands, in case the room is thin), or **Needs a host** (everything else — a lobby or host-driven round; the schedule creator is nudged when the lobby lands). Picking a game shows the matching hint under the form. The self-running and timer sets are disjoint from `LOBBY_GAME_TYPES`, and the countdown set is a subset of it, by test (discovery-4; P4 leftover 2026-09-04 — before that Clapback wore *Needs a host* although it started itself).

**Scheduled launches are not gated by the channel allowlist**, and the panel says so under the channel picker: the list governs games members start themselves with `/games play`; a schedule (and a feature-rotation room) posts wherever it was pointed. Decision 2026-09-04 (platform-31): prod's own daily Risky Rolls schedule posts into a channel that is not on the list, so gating at create time would have refused it; the copy on Global Config and the scheduler was corrected instead of the behaviour.

### Meta surfaces

`/recap` reads the current channel's session window — the past 30 minutes of games — and renders highlights based on each game's final payload: most divisive WYR question, guiltiest NHIE player, best TTL liar, hottest hot take, and so on. The window is kept open by play, not only by starts and ends: every payload write (`modify_payload` — a vote, a pose, a join, an advance) touches the channel's session (`touch_session`, at most once per game per 30 s), moving `last_game_at` forward and merging the roster rebuilt from the payload, so a member typing `/recap` forty minutes into an AMA sees the session rather than "No active session found" (platform-22), and a joiner is in the recap from the moment they join. Ending a game merges its roster too — a paying end through `_fire_session_join`, a bare end through `update_session` directly — so the start-time call's host-only roster is completed by the end of the game. Games with no joined roster (`NO_ROSTER_TYPES`: the daily Photo Challenge post, ffa cards) never open or extend a session; `update_session` answers `None` for them, so a bot post is not a game night. Anonymous-submission games (`ANON_ROSTER_TYPES`: FFA) keep the host-only session their launch opened but their roster is paid and never merged — not by the touch, the paying end or the bare end. A lobby the idle sweep cancels (`reason = 'lobby_timeout'`) opens no session either: its join list is not a game the room played. `/games help` opens the grouped game picker described under *Meta & admin commands*. `/support` (top-level, bot-wide — not under `/games`) posts a static support-server invite; `/games support` was the same thing under a games-shaped name and was removed 2026-07-28.

### Close & archive

Every game's Close/End path opens a confirm popup ("Are you sure you want to end this game?" → Yes/No), skipped when a mod passes `force:true`. On confirm (or on a mod's `force:true`): the view disables, the game's final payload is copied into the history archive, and the live-game row is freed. `/games end`, by its host or (with `force:true`) a mod, runs this teardown; AMA runs its extra view/message cleanup first so nothing is orphaned. A 24-hour sweep (`games/utils/expiry_service.py`) closes orphans — hourly, and once more at the end of boot recovery (`recovery.recover_active_games`), so a game that expired while the bot was down is archived immediately rather than keeping dead buttons and a "busy" channel for up to an hour (platform-30). Boot recovery hands every other live row to its cog's `recover_game`, and the lobby games **branch on `state`**: a `joining` row gets its lobby view re-registered on the anchor message (Rushmore, MLT, Story, Hot Takes, and since 2026-09-04 Clapback, Name Your Price and Two Truths — Two Truths' Start Guessing now writes `state = 'guessing'` so recovery can tell a lobby from a game in progress, and Clapback's recovered lobby is bound as a persistent view so it has no inactivity timeout of its own), while a row past its start is re-driven or ended gracefully as each game documents. Until then a Clapback lobby was re-driven as a game — an empty roster played five no-op rounds to a 'Winner: Nobody' recap, a joined one crashed at the first vote (clapback-3) — and a Two Truths lobby holding any submission was force-started into guessing past the host's 2-submission floor (vote-games-56). When the sweep closes a game that **paid**, it posts one line in the channel — `📦 Truth or Dare archived after 24h — 45 coins paid to 3 players.` — with mentions suppressed; nothing is posted for an empty lobby, a bot post, or a guild whose economy is off, and a channel the bot can no longer post in is skipped without affecting the archive or the payout (platform-21, decision D2). It is a notice, not a recap, and there is **no inactivity close** behind it — see Non-goals.

**Which end paths pay — all of them.** The economy faucet fires when `end_game` is given `bot=` and `player_ids=`. A game's own completion site builds that roster from locals it has in hand; the two paths that end a game from *outside* it have no such locals, so they rebuild the roster from the stored payload via `games/utils/game_roster.py` (`roster_from_payload`, one extractor per game type, each mirroring its cog's completion site).

- The **24-hour sweep** (`expiry_service.py`) pays. Hosts routinely never press End, so before 2026-07-29 every swept game paid nobody — all 18 Truth or Dare games in the history ended this way. A game whose live view exposes `close_now` (AMA) is closed through it first, so its recap posts and pays the way the feature rotation already ended it (social-prompt-33); if that close raises, the game falls through to the archive-and-pay path.
- **`/games end`** — host confirm or mod `force:true` — (`force_end_active_game`) pays. This is the normal close method for several games, not only an abort, so it credits the room the same way.

A game type with no joined roster — ffa banner posts, Photo Challenge — resolves to an empty roster and pays nobody, which is correct: they are posts, not games players sign into (Photo Challenge is paid by the economy's own `photo_post` trigger instead). An abandoned lobby lands on that same empty roster, which is the whole anti-farm gate: aborting a game that never got going costs nothing, and leaving one open all day earns what it played. A malformed payload costs its own game a roster, never the sweep it was found in.

Because every path now routes through `end_game`, its `DELETE`-first claim is what keeps a game from paying twice when a sweep, a force-end, and a host pressing End race each other.

**What `end_game` records is not gated on the caller knowing the roster.** Since 2026-09-04 a bare call — a lobby timeout, an empty-bank unwind, crash cleanup — archives the game's **stored** payload when none is passed, and when it names neither `player_ids` nor a `player_count`, the roster and round count are rebuilt from that payload through `game_roster` and recorded (platform-20: half the game types wrote `player_count = 0` and `payload = {}` on every non-completion path, and Play Statistics, `/recap` and the Ping Response report all read those zeros). Recording never pays: the faucet still fires only on an explicit `player_ids`. The archived `guild_id` is copied from the live row (platform-19: every bare call wrote 0 — 51 prod rows invisible to the guild-filtered dashboard, thirty of them the daily photo post) and re-derived only when the row still says 0 — from the bot's channel cache when a bot is passed, else from the channel allowlist. An optional `reason` (`'lobby_timeout'`, `'crash'`, `'expired'` — the sweep passes the last) lands in the archived payload so the dashboard can tell an abandoned lobby from a game that was played (clapback-9). Clapback's two lobby-death paths use it: the lobby view's inactivity timeout and a crash inside Start both go through `_cancel_game`, which reads the stored payload and archives the roster count, the rounds played and the reason — a lobby that died with six joined and no host reads as exactly that. `end_game` returns a `GameEnd` (guild, counts, `coins_paid`) or `None` when another call already claimed the game; `pay_game_rewards` returns the coins it credited to make that possible. The Ping Response report treats a photo history row at `player_count = 0` as unknown (blank) rather than a failed ping, since the daily post archives before anyone replies (photo-external-104).

**A transient Discord failure must not archive a game (2026-09-10).** discord.py
retries `{500, 502, 504, 524}` unconditionally but **not 503**
(`discord/http.py:765`), so a 503 comes straight out of `channel.send` with no
attempt at all. `games/utils/send_retry.py` holds the two halves of the answer:
`retry_transient(op)` — three attempts, 1s then 2s apart, retrying a 5xx or a
dead connection and re-raising anything under 500 at once (a 403 will not come
good on the second try, and sleeping on it parks a game loop) — and
`is_transient(exc)`, the same classification a crash handler asks afterwards, so
the two never keep drifting lists of status codes. Every Clapback phase card and
every Hot Takes take card goes out through it.

What survives the ladder is then **classified rather than blanket-archived**.
Clapback's `_play` waits 60s and re-drives itself once off its round
checkpoints, then leaves the game frozen-but-whole (`clapback_spec.md` §5.1);
Hot Takes' Start Voting leaves the row for `recover_game` without an in-process
re-drive, since a button callback is not a loop it can re-enter. Either way the
live-game row survives, which is the point: the row is what `recover_game`
resumes from, what `/games end` archives and *pays*, and what the 24h sweep
archives and pays. A non-transient error still archives with `reason="crash"` —
a genuinely broken game must not become an immortal row.

This was not theoretical. Clapback game `959cd749` was four rounds into five
with four players when the next matchup's send returned 503; the blanket
`except Exception` called `end_game`, deleting the row `recover_game` would
have picked up and skipping the `bot=`/`player_ids=` that pay a roster. Four
played rounds paid nothing. Hot Takes carried a worse version of the same
handler — a bare `end_game(db, game_id)` with no payload, no bot and no roster.
The trade taken knowingly: a retried send can post a card twice if Discord
accepted the first attempt and lost the response.

## Coin wagers (duel + group games)

All six duel/group games (Pressure Cooker, Quickdraw, Hot Potato, Hot Potato
Group, Chicken, Musical Chairs) accept an optional `wager:` amount on their
challenge/start command: equal ante from every player, winner takes the pot
minus an **optional house rake** (`wager_rake_pct`, default 0 — ships dark;
when priced, the cut is named on the payout announcement so the arithmetic
visibly adds up; refunds and single-stake pots are never raked). Escrow lives
in `econ_game_wagers` (economy side, migration 094)
and settles through the shared terminal-state seam — see
`docs/economy_spec.md` §6 and `docs/plans/economy-sinks-round-2.md` stage 4b.
The rule that inverts this module's usual one: `pay_game_rewards` swallows
every error because economy must never block game flow, but an escrow
**debit** raises and refuses the join/accept — you cannot enter a wagered
game you can't pay for.

A wager replaces the nickname stake: a wagered game with no custom `stakes:`
text records "Coins on the line — winner takes the pot." as its stakes and
resolves announce-only — no rename button, no nickname preflight. The rename
flow only runs when neither `stakes:` nor `wager:` is given (the default
"name" stake); see `docs/dk_pvp_games_suite_spec.md` §4.

## Economy integration

Games are wired into the economy quest system. Quest-relevant actions call `fire_member_trigger` (`bot_modules.economy.game_rewards`) to credit a member's economy quest progress — for example AMA credits an `ama_ask` trigger when a question actually becomes visible (on submit in unfiltered mode, on host approval in screened mode; AI-seeded idle questions and rejected questions never pay). Photo Challenge payout is handled by the economy directly (`EconomyCog._on_photo_post`): a member's image post in the configured photo channel pays the `photo_post` quest on the post itself — no reactions needed — the card itself just sets the prompt. Several other game cogs (`ffa`, `clapback`, `mlt`, `price`, `rushmore`, `traditional`, `nhie`, `wyr`) import the same game-rewards path. Credit is best-effort: an economy failure never unwinds a game.

## Permissions

**Bot needs:** Send Messages, Embed Links, Read Message History, Attach Files (Photo Challenge and card renders), Use External Emojis, Manage Messages (so `/games play compliment` can self-delete its public ping). The bot does **not** need Manage Nicknames — that's a Pressure Cooker requirement only.

**User needs:**
- Everyone can run every game command, subject to the channel allowlist and per-guild enable flag.
- Ending a game (`/games end`) is allowed for the game's host, or a Mod/Admin (who can also pass `force:true` to skip the confirm). `/games config game-status` requires Mod/Admin (Manage Server or Administrator). On the three reactive round games (WYR, NHIE, MLT) **Next** and the board's **🏁 End Game** are also open to holders of the configured Game Host role, and Next to any voter on a scheduled launch once the round has been open long enough (see "Pacing and endings").
- `/games join`/`/games leave` are self-service; adding or removing *another* player requires the host, a Mod/Admin, or the configured Game-Host role.
- External tracking (web) requires Mod.
- Dashboard config writes need `mod`; dashboard content authoring needs Administrator OR the configured editor role.

## Non-goals

- **No cross-channel state.** Each channel runs one game at a time; the session window is also per-channel.
- **No cross-guild or in-app leaderboards yet.** History and external-game messages are collected per guild, but no leaderboard surface is rendered.
- **No per-user game settings.** Configuration is per-guild or per-channel only.
- **No pre-game RSVP.** Players join by clicking a button on the live embed.
- **No mid-game inactivity timeouts** except AMA's per-question lifecycle, the lobby idle close (a `joining` lobby that has sat for the configured hour with fewer players than its game can start with — the Clapback lobby's own 10-minute view timeout was the model; see "Start countdown + host nudge"), and the 24-hour orphan sweep. The round timer on WYR/NHIE/MLT is *pacing* the host or an admin opts into (a round closes on a clock and the next opens), not an idle close — a host-paced game still waits for a press. The host is trusted to close the game; the sweep is the safety net. Reaffirmed 2026-09-04 (games deep review, decision D2): the sweep's one-line "archived, N coins paid" notice is the fix for a payout that arrived a day later out of sight, and End buttons on the reactive boards are a defect fix — neither is an inactivity close, and platform-21's proposed idle-close was declined. **Truth or Dare (traditional) is the one named exception** (trivia-tail-84, 2026-09-04): opting in and play are a single `joining` board, so the lobby idle close could never tell an empty room from a game in progress, and 18 of 19 prod games were left to the sweep; its per-game dial (`idle_minutes`, default 20, 0 = off) ends a quiet room through the same recap-and-pay path as its End Game.
- **No matchmaking.** Pairings are random — no skill or history awareness.
- **No persistent seasons.** History is raw rows only.
- **No voice, music, or TTS integration.** Games are text + embed only.
- **Pressure Cooker and Risky Rolls are not part of this suite.** They share the game registry for naming/icons but have their own entry points and infrastructure; Pressure Cooker is documented in [[pressure-cooker-spec]].

> **Note — economy is no longer a non-goal.** Earlier versions of this spec claimed games have "no XP/economy integration." That is now false: games credit economy quest triggers and Photo Challenge registers reply-cards. See **Economy integration**.

### Per-channel (dashboard)

- **Channel allowlist** — only allowlisted channels accept any **party**-game command. It does not reach the duels and group elimination games, which gate on their own per-game `channel_allowlist` in `duel_config` and nothing else; their six panels claimed otherwise until 2026-08-30. See `dk_pvp_games_suite_spec.md`. Nor does it reach dashboard-scheduled launches or feature-rotation rooms, which post where they were pointed (see "Scheduled launches"); the Global Config hint said "party games can only be started in these channels" until 2026-09-04 and now says which door it guards.
- **LegitLibs `max_tier`** — hard cap on tier (default 4); higher requests silently downgrade.

### Environment / files

- No API key is needed for the question games: the AI fallback and its per-game prompt file were removed 2026-07-28; every question game is bank-only.
- A LegitLibs starter pack of templates (`bot_modules/games/templates_seed.json`, `data.SEED_PATH`) is loaded into the shared global pool (`guild_id = 0`) on every boot, one `INSERT … WHERE NOT EXISTS` per template keyed on (global, title, body): a guild that has authored its own templates still gets the pack once, and re-runs add nothing. The file carries no ids — `template_id` is an INTEGER PRIMARY KEY the database assigns. Until 2026-09-04 the pack had never loaded anywhere: the path pointed at the repo root, the rows carried string ids, and a "skip if any published template exists" guard hid both (trivia-tail-82). Tags are stored the way the dashboard stores them (comma-separated), and the gameplay reader accepts either that or a JSON list.
- The LegitLibs **blank vocabulary** — `legitlibs_blank_axes` (the parts of
  speech, and the domains and forms valid under each) and
  `legitlibs_blank_prompts` (the wording and examples a fill modal shows) — is
  **seed content, edited by migration only**. It is read by `data.get_axes` /
  `data.get_prompts` and by `validate_template`, exposed read-only at
  `GET /api/games/legitlibs/axes` for the template editor's dropdowns, and has
  no create/update/delete surface anywhere. That is a **decision, not an
  oversight** (finding #91 of the 2026-08-29 config audit, closed won't-do
  2026-09-11): both tables are **bot-wide**, carrying no `guild_id` and listed
  in `guild_purge_service.GLOBAL_TABLES` as "Bot-wide by design", so any edit
  from any guild's dashboard would reword the prompts and re-gate the domains
  for **every** guild the bot is in — including guilds this instance does not
  run. Raising an axis's `min_tier` can also invalidate templates that are
  already published, because `validate_template` re-checks the tier rule at
  load. Nothing in Discord or on the dashboard claims this content is editable,
  so there is no unenforced promise to fix; the audit's own note recorded the
  cost of closing it as "a new CRUD surface with cascading pos/domain/form and
  min_tier rules: a feature, and a decision about who may reword the in-game
  prompts". **To revisit**, the cross-guild question has to be answered first —
  either per-guild rows (a `guild_id` column plus a fallback chain to the
  seeded set) or an explicit bot-owner-only surface — and published templates
  have to be revalidated when an axis tightens.
  `tests/web/test_games_legitlibs_vocabulary_is_seed_content.py` fails if
  any write path appears anywhere under `src/` outside a migration — it scans
  the SQL across the whole tree, not just the route modules, because the
  layering rule would put a spec-compliant editor's writes in
  `cogs/games_legitlibs/data.py` rather than in a route.

### In-memory

- The external-tracking watch cache (`guild → {(bot, channel) → kind}`) is warmed on load and refreshed by the dashboard through `GamesExternalCog.refresh_watch_cache` after every write, so the `on_message` hot path never touches the DB. A write that skipped that refresh would be a silent no-op until the next restart. Keyed on the pair, not the bot, so a bot playing in several channels is matched in all of them.
- A per-game payload lock serialises mutations within one game; the lock is freed on game close.

## Stored data

Per-guild content (the seeded question bank, LegitLibs templates and their revision history, AI-prompt overrides) plus per-game runtime state (the live game's payload, the session window, audit channel and editor-role settings, allowlisted channels, the anonymous-features audit trail and its retention setting) and an archive of every finished game's final payload. External-tracking config and raw banked bot messages are stored per guild. User ids appear inside game payloads and the history archive. Photo Challenge registers card metadata for the economy `photo_post` payout.

LegitLibs additionally stores a small vocabulary table (parts of speech, domains, forms) and per-blank prompt text used to render fill modals, plus an anti-repeat window of the last few templates used per guild, channel tier caps, and user-submitted abuse reports on filled-in answers.

No DM data is stored. No filesystem cache outside the prompt-config file and the LegitLibs seed file.

## Not Yet Built / Roadmap

The following were described as current behavior in earlier versions of this spec but are **not implemented today**. The underlying *capabilities* they described mostly still exist — they're just reached a different way now (usually the dashboard), or were removed outright. They're recorded here so the design intent isn't lost.

### Never-built or removed command surfaces

- **`/games allow-channel | disallow-channel | list-channels`** — no such slash commands exist. Channel allowlisting is real and enforced, but is managed from the web dashboard. Only the *slash-command interface* was ever documented; it was never wired. (The embed/logic helpers for these strings still linger in `games_config/logic.py` and `embeds.py` but nothing calls them.) A future slash interface for allowlisting is a reasonable roadmap item.
- **`/games audit-channel [channel]`** — likewise unbuilt as a slash command. The audit channel is a live feature, set from the dashboard (`games_audit_channel`).
- **`/games portal-grant | portal-revoke | portal-list`** — removed. The `games_portal_access` table these wrote was dropped in migration `041_drop_games_portal_access.sql`. Dashboard/Games access is now governed solely by Discord admin/mod permissions plus the `games_editor_role` (Game Host role) — the editor role **supersedes** the old portal sign-in allowlist concept.
- **`/legitlibs-admin reload | cap-tier | preview | list | killswitch | enable`** — no such commands exist. LegitLibs content management, tier caps, and template preview live in the dashboard. The module-level **kill switch** described in older specs has been removed entirely (no `killswitch` code remains). LegitLibs tier caps are configured per channel from the dashboard, not via a slash command.

### Removed gameplay concepts

- **Consent system (`/consent`, `/consent-status`).** Fully deleted. The empty `games_consent/` directory went in `49a02867` and the orphan `games_consent` table — one row, zero code references — was dropped in migration 184. There is no per-user opt-in flag and no game blocks on consent. If per-user consent gating is ever revived, it would be a new build, not a re-enable of paused wiring. (Note: unrelated "consent" systems exist elsewhere — DM permissions and Rules Watch — and are *not* part of the games suite.)
- **LegitLibs Hot Seat mode.** Older specs listed a third "Hot Seat" LegitLibs mode as a stub. It has been removed; only `classic` and `quiplash` exist today. A one-at-a-time LegitLibs variant could be revisited as a roadmap item.

### Collection-without-surface

- **External game leaderboards.** External tracking and the `games_external_messages` collector bank raw messages from external bots. **Economy payout is now built** (Gamebot CAH → `party_game`/`game_win`; Cat Bot catches → tiered `cat_catch` — see `docs/plans/external-game-economy.md`), but our own *leaderboards/streaks* over those games (games-played, win-rate, catch counts by rarity) are still not surfaced — a roadmap item on top of the same banked data.
- **Hot Potato style points (metric tracked, never shown).** Every Hot Potato game already computes and accumulates **style points** — 10 per second a player spends holding the potato in the danger zone (last 30% of the timer) — into `hot_potato_style (guild_id, user_id, total_points)` via `compute_style_points` + `add_style_points`. The per-game figure appears on the result card, and since 2026-09-04 the same line quotes the player's **running total** ("now has 174 style points" — `hot_potato/db.get_style_total`, the cumulative table's only reader). There is still no leaderboard, command or profile line; a fuller pass could track games played / wins / explosions (losses) / longest hold alongside it. This slots into the deferred participation-based cross-game standings roadmap (see memory: games progression roadmap) rather than being a one-off.
